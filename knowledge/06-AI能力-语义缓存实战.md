## 为什么需要语义缓存？

> **真实场景：** 某电商客服 Agent 上线后，每天收到 10,000 次咨询，其中 35% 是 FAQ 类问题（"怎么退货""物流几天到""怎么开发票"）。每次都用 GPT-5.6 Sol 回答，月账单 8,000 美元。团队发现这些问题答案基本不变，但用户问法千变万化——"怎么退货""如何退货""退货流程""我要退货怎么操作"——如果用精确缓存，命中率不到 5%。上了语义缓存后，FAQ 命中率提升到 80%，月账单降到 3,000 美元。

**语义缓存的核心价值：不是"记住一样的问题"，而是"理解一样的意思"。**

**类比：图书馆管理员 vs 智能搜索引擎**

```
精确缓存 = 图书馆管理员（按书名查找）
  你问："怎么退货" → 找到"怎么退货"这本书 → 命中
  你问："如何退货" → 找不到 → MISS（书名不同，但内容一样）

语义缓存 = 智能搜索引擎（按语义查找）
  你问："如何退货" → 理解你的意思是"退货流程" → 找到最相关的内容 → 命中
```

### 第一讲：精确缓存 vs 语义缓存

```
┌──────────────────────────────────────────────────────────────┐
│              精确缓存 vs 语义缓存                               │
│                                                              │
│  精确缓存：                                                   │
│    Key: "怎么退货"  ──MD5──→ abc123                          │
│    Key: "如何退货"  ──MD5──→ def456  ← 不同！Miss！          │
│    命中率：低（用户必须一字不差）                              │
│                                                              │
│  语义缓存：                                                   │
│    Key: "怎么退货"  ──Embedding──→ [0.12, 0.34, ...]        │
│    Key: "如何退货"  ──Embedding──→ [0.13, 0.32, ...]        │
│    相似度：0.97 > 阈值 0.85 → 命中！                          │
│    命中率：高（不同问法都能命中）                              │
└──────────────────────────────────────────────────────────────┘
```

```
┌──────────────────────────────────────────────────────┐
│ 阈值   │ 命中率 │ 准确率 │ 适用场景                    │
├──────────────────────────────────────────────────────┤
│ 0.95   │ 低     │ 极高   │ 严格 FAQ（退货政策等）      │
```

### 第二讲：语义缓存实现

```python
# src/ai-service/cache/semantic_cache.py — 语义缓存完整实现
import hashlib
import numpy as np
from redis import Redis
from openai import OpenAI

class SemanticCache:
    """
    语义缓存：两级缓存策略

    第一级：精确缓存（最快，O(1) 查找）
    第二级：语义缓存（慢一点，但命中率高）

    为什么两级？精确缓存只要 1ms，语义缓存需要向量计算 ~50ms。
    先走精确缓存，99% 的重复问题直接命中，省下向量计算时间。
    """

    def __init__(self):
        self.redis = Redis(host='localhost', port=6379)
        self.client = OpenAI()
        self.similarity_threshold = 0.85  # 相似度阈值

    async def get(self, query: str) -> str | None:
        """获取缓存：先精确匹配，再语义匹配"""
        # 第一级：精确匹配（最快）
        exact_key = f"cache:exact:{hashlib.md5(query.encode()).hexdigest()}"
        cached = self.redis.get(exact_key)
        if cached:
            return cached.decode()

        # 第二级：语义匹配（向量搜索）
        embedding = await self.get_embedding(query)
        # 在 Redis 中搜索相似向量
        # VECTOR_RANGE 0.05 表示相似度 > 0.95（距离 < 0.05）
        similar = self.redis.ft("semantic_cache").search(
            f"@embedding:[VECTOR_RANGE 0.05 $vec]",
            {"vec": embedding}
        )
        if similar.docs:
            return similar.docs[0].answer

        return None  # 缓存未命中

    async def set(self, query: str, answer: str):
        """写入缓存：同时写精确缓存和语义缓存"""
        embedding = await self.get_embedding(query)

        # 写精确缓存（1小时过期）
        exact_key = f"cache:exact:{hashlib.md5(query.encode()).hexdigest()}"
        self.redis.setex(exact_key, 3600, answer)

        # 写语义缓存（存储向量 + 答案）
        self.redis.hset(
            f"cache:semantic:{hashlib.md5(query.encode()).hexdigest()}",
            mapping={"query": query, "answer": answer, "embedding": embedding}
        )

    async def get_embedding(self, text: str) -> list[float]:
        """获取文本向量"""
        response = await self.client.embeddings.create(
            model="text-embedding-3-large",  # 2026推荐：1024维，性价比最高
            input=text
        )
        return response.data[0].embedding
```

### 第三讲：LangChain 精确缓存——一行代码省钱

#### 精确缓存 vs 语义缓存 互补

|          | 精确缓存（LangChain）  | 语义缓存（向量）       |
| -------- | ---------------------- | ---------------------- |
| 命中条件 | 输入**完全一样**       | 输入**语义相近**       |
| 实现方式 | 一行 `set_llm_cache`   | 向量数据库 + Embedding |
| 适用场景 | 开发调试、高频同一问题 | 客服 FAQ、问法多变     |
| 命中率   | 低（需要一字不差）     | 高（不同问法都能命中） |
| 成本     | 几乎零                 | 需要维护向量库         |

#### 一行开启精确缓存

```python
# src/ai-service/cache/langchain_cache.py — LangChain 精确缓存
from langchain_core.globals import set_llm_cache
from langchain_core.caches import InMemoryCache

# 一行开启，所有 LLM 调用自动走缓存
set_llm_cache(InMemoryCache())

llm.invoke("解释什么是 Agent")  # 第一次：请求 API，慢
llm.invoke("解释什么是 Agent")  # 第二次：命中缓存，秒回、不花钱
```

#### 三种缓存后端

| 后端            | 用途             | 代码                                      |
| --------------- | ---------------- | ----------------------------------------- |
| `InMemoryCache` | 进程内，开发测试 | `set_llm_cache(InMemoryCache())`          |
| `SQLiteCache`   | 落文件，重启仍在 | `set_llm_cache(SQLiteCache(".cache.db"))` |
| `RedisCache`    | 多实例共享，生产 | `set_llm_cache(RedisCache(redis_client))` |

1. 精确缓存匹配字符串完全相同，语义缓存匹配向量相似。两级策略：精确缓存 O(1) 只需 1ms，先走它可拦截 99% 的完全重复请求；未命中再走语义缓存（~50ms 向量计算），覆盖不同问法。这样既快又全。

### Step 2：实现 Embedding 生成函数（10 分钟）

**任务：** 调用 OpenAI Embedding API，封装成可复用的函数。

**具体操作：**

```python
from openai import OpenAI
import numpy as np

client = OpenAI()

def get_embedding(text: str, model: str = "text-embedding-3-large") -> list[float]:
    """获取文本向量（1024维）"""
    response = client.embeddings.create(model=model, input=text)
    return response.data[0].embedding

def cosine_similarity(a: list[float], b: list[float]) -> float:
    """计算余弦相似度"""
    a, b = np.array(a), np.array(b)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

# 验证：两个相似问题的相似度
v1 = get_embedding("怎么退货")
v2 = get_embedding("如何退货")
v3 = get_embedding("今天天气真好")
print(f"'怎么退货' vs '如何退货': {cosine_similarity(v1, v2):.4f}")  # 预期 > 0.85
print(f"'怎么退货' vs '今天天气真好': {cosine_similarity(v1, v3):.4f}")  # 预期 < 0.5
```

**✅ 验证标准：** 相似问题相似度 > 0.85，不相关问题相似度 < 0.5。

**提示要点：**

2. **决策：** 你选择了两级缓存（精确+语义），还是只用语义缓存？如果是两级，精确缓存拦截了多少比例？这个比例值不值得多维护一套精确缓存逻辑？

3. **取舍：**
   - 语义缓存的 Embedding API 调用也要花钱（text-embedding-3-large 每 1M tokens $0.13）。如果缓存命中率太低，Embedding 调用成本可能超过节省的 LLM 成本。你的命中率阈值是多少？

   - 防"Embedding 模型切换后缓存全废"——换了模型，向量空间变了，旧缓存全部不可用，必须设计好迁移策略。
