## 为什么需要意图识别？

### 一个真实的翻车场景

```
用户："帮我查一下那个订单"

Agent 内部：
  关键词匹配 → "订单" → 触发"查订单" Skill
  调用 query_order(userId) → 返回最近 20 个订单

用户："不是这个，我说的是上次退的那个"

Agent 内部：
  关键词匹配 → "退" → 触发"售后处理" Skill
  调用 create_return() → "请问您要退哪个订单？"

用户："我说的是查！不是退！你听不懂人话吗？"

Agent 内部：
  关键词匹配 → "退" → 又触发"售后处理" Skill
  调用 create_return() → "请问您要退哪个订单？"

用户："转人工！！！"（愤怒值爆表）
```

**这就是意图识别失败的真实后果：**

- 关键词匹配太机械，"退"出现在"退的那个"里就触发退货
- 没有上下文理解，"那个"指代什么完全不知道
- 用户说了"查"但"退"字优先级更高，导致误判
- 连续两次错误 → 用户信任崩塌 → 转人工 → 差评

**好的意图识别应该做到：**

- "查一下那个订单" → 理解"查"是主意图，"那个"指代上下文中的订单
- "上次退的那个" → 理解"退的那个"是修饰语，主意图是"查"
- 不只看关键词，还要看语义和上下文

> **类比：餐厅服务员。** 差的意图识别 = 服务员只听关键词，顾客说"不要辣的"→ 听到"辣"就上麻辣锅。好的意图识别 = 服务员理解整句话，顾客说"不要辣的，来点清淡的"→ 推荐清蒸鱼。

### 方案1：关键词匹配（最快）

#### 1.1 类比：查字典

```
┌──────────────────────────────────────────────────────────┐
│  类比：关键词匹配 = 查字典                                │
│                                                          │
│  你说"苹果"，字典翻到 A 开头 → 找到"苹果"                │
│  → 速度极快，但如果你说"那个红红的水果"，字典就翻不到     │
│                                                          │
│  优点：毫秒级、零成本、不需要 AI                          │
│  缺点：只能匹配字面，不懂语义、不懂上下文                 │
└──────────────────────────────────────────────────────────┘
```

#### 1.2 实现

```typescript
// agent-platform/src/agent-tools/intent/keywordIntent.ts
// 方案1：关键词匹配 —— 最快但最机械

const INTENT_KEYWORDS: Record<string, string[]> = {
  查订单: ["查订单", "订单", "ORDER", "我的订单", "买了什么", "购买记录"],
  查物流: ["物流", "到哪了", "发货", "快递", "配送", "送到哪"],
  退货: ["退货", "退款", "退钱", "不想要了", "想退", "退掉"],
  咨询: ["多少钱", "有没有", "推荐", "怎么样", "好用吗", "评价"],
  闲聊: ["你好", "谢谢", "在吗", "天气", "今天星期几"],
};

export function keywordIntent(message: string): {
  intent: string;
  confidence: number;
} {
  // 遍历所有意图的关键词列表
  for (const [intent, keywords] of Object.entries(INTENT_KEYWORDS)) {
    for (const kw of keywords) {
      if (message.includes(kw)) {
        // 找到匹配 → 高置信度返回（关键词匹配假设置信度 0.9）
        return { intent, confidence: 0.9 };
      }
    }
  }
  // 没有任何关键词匹配 → 返回"未知"
  return { intent: "未知", confidence: 0 };
}
```

#### 1.3 关键词匹配的致命问题

```
❌ 问题1：一词多义
  用户："这个能退吗？" → 匹配"退" → 意图="退货" ✅
  用户："退一步说..." → 匹配"退" → 意图="退货" ❌（误判！）

❌ 问题2：同义不同词
  用户："这个能还回去吗？" → 没有关键词 → 意图="未知" ❌
  （用户想退货，但说了"还回去"而不是"退货"）

❌ 问题3：不懂否定
  用户："我不是要退货，我是想问怎么查物流"
  → 匹配"退货" → 意图="退货" ❌（完全理解反了！）
```

### 方案2：LLM 语义识别（最准）

#### 2.1 类比：找一位懂你的助手

```
┌──────────────────────────────────────────────────────────┐
│  类比：LLM 识别 = 找一位懂你的助手                        │
│                                                          │
│  你说："上次那个红红的水果，在哪买的来着？"              │
│                                                          │
│  关键词匹配：没有"苹果"关键词 → 未知 ❌                   │
│                                                          │
│  LLM 助手：                                               │
│    "红红的水果" → 可能是苹果或草莓                        │
│    "上次那个" → 结合上下文，上次对话提到过苹果            │
│    "在哪买的" → 意图是查询购买记录                        │
│    → 判断：意图="查订单"，商品="苹果"                    │
│                                                          │
│  优点：能理解语义、上下文、指代                           │
│  缺点：有延迟（200-500ms）、有成本（API 调用费）          │
└──────────────────────────────────────────────────────────┘
```

#### 2.2 实现

```typescript
// agent-platform/src/agent-tools/intent/llmIntent.ts
// 方案2：LLM 语义识别 —— 最准但最慢

import { ChatCompletionService } from "../../services/chatCompletion";

interface IntentResult {
  intent: string;
  confidence: number;
  reasoning: string;
  method: "llm";
}

const INTENTS = ["查订单", "查物流", "退货", "商品咨询", "闲聊", "投诉"];

export async function llmIntent(
  message: string,
  history?: string[],
): Promise<IntentResult> {
  const chatService = new ChatCompletionService();

  const response = await chatService.complete({
    // 使用 GPT-5.6-flash（$0.025/M input）做意图识别
    // flash 足够做分类任务，不需要 sol 的推理能力
    model: "gpt-5.6-flash",
    messages: [
      {
        role: "system",
        content: `你是一个意图识别专家。分析用户消息，分类为以下意图之一：
${INTENTS.join("、")}

返回 JSON 格式：
{
  "intent": "意图名称",
  "confidence": 0.0-1.0,
  "reasoning": "判断理由（一句话）"
}

规则：
- 如果用户明确说"退货/退款/退钱"，intent="退货"
- 如果用户说"退的那个"但主要问"查"，intent="查订单"
- 如果用户只是问候，intent="闲聊"
- 如果无法判断，intent="未知"，confidence=0`,
      },
      {
        role: "user",
        content: `历史对话：${history?.join(" | ") || "无"}
用户消息：${message}`,
      },
    ],
    temperature: 0, // 分类任务温度设为0，确保结果稳定
    maxTokens: 150,
    responseFormat: { type: "json_object" }, // 强制 JSON 输出
  });

  const result = JSON.parse(response.choices[0].message.content ?? "{}");
  return {
    intent: result.intent || "未知",
    confidence: result.confidence || 0,
    reasoning: result.reasoning || "",
    method: "llm",
  };
}
```

### 方案3：混合方案（推荐）✅

#### 3.1 类比：医院分诊台

```
┌──────────────────────────────────────────────────────────┐
│  类比：混合方案 = 医院分诊台                              │
│                                                          │
│  第一关：护士（关键词匹配）                               │
│    病人："我发烧了"                                       │
│    护士看一眼："发烧 → 挂内科" ✅ 10秒搞定                │
│                                                          │
│  第二关：医生（LLM 语义识别）                             │
│    病人："我最近总感觉没力气，吃不下饭，有时候还头晕..."  │
│    护士判断不了 → 交给医生综合诊断                        │
│    医生："可能是贫血，也可能是甲减，建议先验血"           │
│                                                          │
│  策略：80% 的病人在护士那关就搞定了，                      │
│        只有 20% 需要医生深入诊断                          │
│        → 速度快 + 成本低 + 准确率高                       │
└──────────────────────────────────────────────────────────┘
```

#### 3.2 实现

```typescript
// agent-platform/src/agent-tools/intent/hybridIntent.ts
// 方案3：混合方案 —— 关键词（快） + LLM（准）✅ 推荐

import { keywordIntent } from "./keywordIntent";
import { llmIntent } from "./llmIntent";

interface HybridIntentResult {
  intent: string;
  confidence: number;
  method: "keyword" | "llm";
  reasoning?: string;
}

export async function hybridIntent(
  message: string,
  history?: string[],
): Promise<HybridIntentResult> {
  // 第一步：关键词快速匹配（毫秒级，零成本）
  const keywordResult = keywordIntent(message);

  // 如果关键词匹配成功且置信度 ≥ 0.9，直接返回
  // 为什么要 0.9？因为关键词匹配是"字面匹配"，置信度默认 0.9
  // 留下 0.1 的空间给可能有歧义的情况
  if (keywordResult.intent !== "未知" && keywordResult.confidence >= 0.9) {
    return {
      intent: keywordResult.intent,
      confidence: keywordResult.confidence,
      method: "keyword",
    };
  }

  // 第二步：关键词未命中或置信度不够 → 用 LLM 语义识别
  // 这一步有延迟（200-500ms）和成本（API 调用费）
  // 但只发生在 ~20% 的请求中
  const llmResult = await llmIntent(message, history);

  return {
    intent: llmResult.intent,
    confidence: llmResult.confidence,
    method: "llm",
    reasoning: llmResult.reasoning,
  };
}
```

### 方案4：三重融合方案（2026 最新）⭐

#### 4.1 为什么需要三重融合？

```
混合方案的问题：
  关键词匹配 → 置信度 0.9 → 直接返回
  但万一关键词匹配错了呢？没有二次验证！

三重融合方案：
  关键词匹配（0.3权重） + 语义向量匹配（0.5权重） + LLM验证（0.2权重）
  → 三个裁判投票，少数服从多数
  → 只有当三个裁判都"不确定"时，才返回"未知"
```

#### 4.2 实现

```typescript
// agent-platform/src/agent-tools/intent/tripleFusionIntent.ts
// 方案4：三重融合 —— 2026 年最新方案 ⭐

import { keywordIntent } from "./keywordIntent";
import { llmIntent } from "./llmIntent";
import { EmbeddingService } from "../../services/embedding";

interface Vote {
  intent: string;
  confidence: number;
  weight: number;
}

export async function tripleFusionIntent(
  message: string,
  history?: string[],
): Promise<{ intent: string; confidence: number; votes: Vote[] }> {
  const votes: Vote[] = [];

  // 裁判1：关键词匹配（权重 0.3）
  // 快但机械，权重最低
  const keywordResult = keywordIntent(message);
  votes.push({
    intent: keywordResult.intent,
    confidence: keywordResult.confidence,
    weight: 0.3,
  });

  // 裁判2：语义向量匹配（权重 0.5）
  // 用 Embedding 计算用户消息与各意图描述的相似度
  // 使用 text-embedding-3-small（$0.02/M token，性价比最高）
  const embeddingService = new EmbeddingService();
  const vectorResult = await embeddingService.classifyIntent(message, [
    "查订单",
    "查物流",
    "退货",
    "商品咨询",
    "闲聊",
    "投诉",
  ]);
  votes.push({
    intent: vectorResult.intent,
    confidence: vectorResult.confidence,
    weight: 0.5, // 语义向量权重最高，因为它平衡了速度和准确度
  });

  // 裁判3：LLM 验证（权重 0.2）
  // 最准但最慢，只在前面两个裁判意见不一致时启用
  // 如果前两个裁判意见一致且置信度 > 0.8，跳过 LLM
  const needLLM =
    votes[0].intent !== votes[1].intent ||
    votes[0].confidence < 0.8 ||
    votes[1].confidence < 0.8;

  if (needLLM) {
    const llmResult = await llmIntent(message, history);
    votes.push({
      intent: llmResult.intent,
      confidence: llmResult.confidence,
      weight: 0.2,
    });
  }

  // 加权投票：计算每个意图的加权总分
  const intentScores: Record<string, number> = {};
  for (const vote of votes) {
    if (vote.intent === "未知") continue;
    intentScores[vote.intent] =
      (intentScores[vote.intent] || 0) + vote.confidence * vote.weight;
  }

  // 选出得分最高的意图
  const bestIntent = Object.entries(intentScores).sort(
    (a, b) => b[1] - a[1],
  )[0];

  return {
    intent: bestIntent?.[0] ?? "未知",
    confidence: bestIntent?.[1] ?? 0,
    votes,
  };
}
```

### 第五讲：HMall 的 IntentAgent

```typescript
// agent-platform/src/agent-tools/intent/IntentAgent.ts
// 完整的意图识别 Agent，带上下文管理

interface IntentAnalysis {
  intent: string;
  confidence: number;
  reasoning: string;
  method: "keyword" | "llm" | "triple_fusion";
  extractedEntities: Record<string, string>; // 提取的实体
}

export class IntentAgent {
  private static readonly INTENTS = [
    "查订单",
    "查物流",
    "退货",
    "商品咨询",
    "闲聊",
    "投诉",
  ];

  /**
   * 分析用户意图
   * @param message 用户消息
   * @param history 最近3轮对话历史
   */
  async analyze(
    message: string,
    history: Array<{ user: string; bot: string }> = [],
  ): Promise<IntentAnalysis> {
    // 格式化历史对话，给 LLM 提供上下文
    const formattedHistory = history
      .slice(-3)
      .map((h) => `用户: ${h.user}\n客服: ${h.bot}`);

    // 使用三重融合方案（生产环境推荐）
    const result = await tripleFusionIntent(message, formattedHistory);

    // 提取实体（订单号、商品名等）
    const entities = this.extractEntities(message);

    return {
      intent: result.intent,
      confidence: result.confidence,
      reasoning: result.votes
        .map((v) => `[${v.intent}:${(v.confidence * 100).toFixed(0)}%]`)
        .join(" → "),
      method: "triple_fusion",
      extractedEntities: entities,
    };
  }

  /**
   * 从用户消息中提取关键实体
   */
  private extractEntities(message: string): Record<string, string> {
    const entities: Record<string, string> = {};

    // 提取订单号：ORDER + 数字 或 6位以上纯数字
    const orderMatch = message.match(/ORDER\d{3,}|\d{6,}/);
    if (orderMatch) {
      entities.orderId = orderMatch[0];
    }

    // 提取快递单号：常见快递单号格式
    const trackingMatch = message.match(/SF\d{12,}|YT\d{12,}/);
    if (trackingMatch) {
      entities.trackingNumber = trackingMatch[0];
    }

    return entities;
  }

  /**
   * 判断是否需要转人工（置信度过低）
   */
  shouldHandoff(analysis: IntentAnalysis): boolean {
    return analysis.confidence < 0.3;
  }
}
```

### 提示词教学：意图分类 Prompt 的设计与落地

> **AI：** 不重讲六要素模板（真源：`03-AI协作构建\03-AI协作构建技能.md`；进阶：`06-AI能力-Prompt工程实战.md`），只讲意图分类场景怎么填。

**① 场景**：意图识别在三种方案中都需要"意图分类 prompt"——关键词匹配靠预定义意图列表，LLM 方案靠 system prompt 做分类，三重融合中 LLM 还要做兜底仲裁。这个 prompt 决定"用户一句话走向哪个技能的入口"，写错一步，整个 Agent 路由全乱。

**② 六要素对照表**：

| 要素     | 意图分类 prompt 填什么                                                                                                                                                                    |
| :------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 角色     | 客服路由器 / 意图分类器（只分类，不回答，不闲聊）                                                                                                                                         |
| 任务     | 把用户消息归入**预定义意图列表**中的某一个，不确定或不在列表中的归入 unknown                                                                                                              |
| 上下文   | 预定义意图列表（含每个意图的判定说明）+ 最近 3 轮对话历史                                                                                                                                 |
| 约束     | ① 只输出 JSON，不解释、不回答用户问题；② 意图必须从预定义列表中选择，不能自创；③ 含"退"字但主意图不是退货时，以语义为准（如"退的那个订单到哪了"→查物流）；④ 置信度低于 0.4 时输出 unknown |
| 参考     | 每个意图 1-2 个示例话术（如："我的订单到哪了"→查物流、"我要退货"→退货）                                                                                                                   |
| 输出格式 | `{"intent": "意图名", "confidence": 0.0-1.0, "reasoning": "一句话理由"}`                                                                                                                  |

**③ 示例 Prompt**（LLM 意图分类，可直接用）：

```
你是客服路由器，负责把用户消息分类到预定义意图之一。

预定义意图（必须从以下列表中选择，不能自创）：
- query_order：用户想查订单状态/详情/金额（如"我的订单到哪了""ORDER123是什么状态"）
- query_logistics：用户想查物流进度/快递位置（如"快递到哪了""什么时候送到"）
- refund：用户想退货/退款/取消订单（如"我要退货""怎么退款"）
- product_inquiry：用户咨询商品信息/价格/库存（如"这个有货吗""多少钱"）
- complaint：用户投诉/不满（如"太慢了""我要投诉"）
- chitchat：用户问候/闲聊（如"你好""在吗"）
- unknown：无法归入以上任何意图，或用户表述模糊无法判断

判断规则：
- 以用户的主意图为准，修饰语不影响分类（"退的那个订单到哪了"→主意图是查物流，不是退货）
- 结合最近 3 轮对话历史判断指代关系（"上次那个"→参考历史中提到的订单/商品）
- 置信度低于 0.4 时输出 unknown

最近对话历史：{history}

只输出 JSON，不要解释、不要回答用户问题：
{"intent": "意图名", "confidence": 0.0-1.0, "reasoning": "一句话理由"}

用户消息："{message}"
```

**④ 反例 + 为什么**：

```
意图分类 prompt：'把用户的话分一下类，你觉得是什么就写什么。'   // ❌
```

错在哪：① 意图列表不预定义——LLM 会自创意图名，下游代码 `switch(intent)` 全部分支 miss，路由失败；② 输出格式不锁 JSON——下游代码 `JSON.parse()` 直接崩；③ 没有 unknown 兜底——LLM 强行为模糊表述分配一个意图，误判后被路由到错误技能，用户看到完全无关的回复。

**⑤ 完成标准**：能独立写出包含**预定义意图列表 / 输出 JSON / unknown 兜底 / 结合历史判断指代**四条款的意图分类 prompt。

## 动手环节：从零实现一个意图识别路由器（代码级）

> **AI：** 指导学习者逐步完成，每步贴代码、每步验证。全程约 90 分钟。
> **总目标：** ① 实现关键词匹配路由；② 接入 LLM 语义识别兜底；③ 实现三重融合加权投票；④ 端到端验证三种方案在同一个输入上的差异。
> **核心约束：** 关键词列表和意图列表必须与本文档的 6 个意图（查订单/查物流/退货/商品咨询/闲聊/投诉）保持一致。

---

### Step 1：实现关键词匹配路由（15 分钟）

**任务：** 用 TypeScript 实现 `keywordIntent()` 函数，6 个意图各配至少 3 个关键词，处理"一词多义"和"否定"问题。

**具体操作：**

1. 定义 6 个意图的关键词映射表
2. 实现匹配逻辑：遍历关键词，返回匹配到的意图和置信度
3. 处理边界：多个关键词命中不同意图时，按优先级排序

**✅ 验证标准：**

- 输入"帮我查一下 ORDER123" → 返回 `{ intent: "查订单", confidence: 0.9 }`
- 输入"我不是要退货，我是想问怎么查物流" → 返回 `{ intent: "查物流" }`（不能因为"退货"关键词而误判）
- 输入"今天天气真好" → 返回 `{ intent: "未知", confidence: 0 }`

---

### Step 2：接入 LLM 语义识别兜底（25 分钟）

**任务：** 实现 `llmIntent()` 函数，用 LLM 做意图分类，输出 JSON 格式。

**具体操作：**

1. 设计 System Prompt：预定义 6 个意图 + unknown，每个意图附带 1-2 个示例话术
2. 调用 LLM（temperature=0，强制 JSON 输出）
3. 解析返回的 JSON，提取 intent、confidence、reasoning

**✅ 验证标准：**

- 输入"上次退的那个订单，现在到哪了？" → intent 应为"查物流"（主意图是"查"，"退的那个"是修饰语）
- 输入"这个能退吗？" → intent 应为"退货"
- 输入"你好啊" → intent 应为"闲聊"

---

### Step 3：实现三重融合加权投票（30 分钟）⭐ 重点

**任务：** 实现 `tripleFusionIntent()` 函数，组合关键词（0.3）+ 语义向量（0.5）+ LLM（0.2）三个裁判。

**具体操作：**

1. 裁判1：调用 Step 1 的关键词匹配
2. 裁判2：用 Embedding 计算用户消息与 6 个意图描述的余弦相似度（可用 mock 代替真实 Embedding 调用）
3. 裁判3：当裁判1和裁判2意见不一致或置信度 < 0.8 时，调用 Step 2 的 LLM
4. 加权投票：`总分 = Σ(置信度 × 权重)`

**✅ 验证标准：**

- 输入"上次退的那个" → 关键词匹配返回"退货"（0.9），语义向量返回"查物流"（0.85），两个裁判意见不一致 → 触发 LLM 验证 → LLM 判断主意图是"查物流" → 最终结果"查物流"
- 输入"帮我查订单 ORDER123" → 关键词和语义向量一致 → 不触发 LLM → 节省一次 API 调用

---

### Step 4：端到端对比验证（20 分钟）

**任务：** 构造 5 个测试用例，分别跑三种方案，记录每种方案的意图、置信度、耗时，填表对比。

| 测试用例             | 关键词结果 | LLM 结果 | 三重融合结果 | 哪种方案最准？ |
| -------------------- | :--------: | :------: | :----------: | :------------: |
| "查一下 ORDER123"    |            |          |              |                |
| "上次退的那个到哪了" |            |          |              |                |
| "这个好不好用"       |            |          |              |                |
| "我要投诉，太慢了"   |            |          |              |                |
| "今天天气不错"       |            |          |              |                |

**✅ 验证标准：** 5 个用例中，三重融合方案至少有 4 个判断正确。能解释每个用例中三种方案结果差异的原因。
