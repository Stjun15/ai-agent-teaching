# Agent Loop

## 先来一个故事：你做一道从没做过的菜

你第一次做"红烧排骨"。打开手机搜菜谱：

1. **看菜谱** 📖 → "先焯水，再炒糖色，最后炖 40 分钟"
2. **动手做** 🔪 → 把排骨丢进开水里焯
3. **尝一下** 👅 → "嗯，焯好了，没血水了"（等一下…还没放盐！）
4. **回看菜谱** 📖 → "哦，炒糖色那步要放盐和酱油"
5. **继续做** 🔪 → 炒糖色，加调料
6. **再尝** 👅 → "味道对了，可以出锅了"
7. **关火** ✅ → 上桌

Agent Loop 就是上面这个循环：**看菜谱 → 动手 → 尝味道 → 回看菜谱 → 继续…** 直到菜做好。

在 AI 的世界里：
- 看菜谱 = **思考（Think）**："我要做什么？需要调什么工具？"
- 动手做 = **行动（Act）**："调用 getWeather 工具"
- 尝味道 = **观察（Observe）**："工具返回了什么？温度对不对？"
- 没做好就继续 = **重复（Repeat）**："拿到结果了，还要继续吗？"

💡 **核心认知：** Agent Loop 不是普通的"一问一答"。它是**带着步骤反复推敲、边做边看、看完再决定下一步**的过程。

---

## 四步拆解（每一步为什么不能少）

| 步骤 | 干什么 | 如果少了它… |
|------|--------|------------|
| **Think** 思考 | 分析现在手里有什么信息，决定下一步 | AI 不知道该干嘛，瞎回答 |
| **Act** 行动 | 调工具，或直接回答用户 | 光想不做，用户永远等不到结果 |
| **Observe** 观察 | 看工具返回了什么结果 | ⚠️ **最容易被忽视！**不看结果，错了也不知道 |
| **Repeat** 重复 | 带着新信息回到 Think | 没做完就停了，用户只拿到半截答案 |

> 🛑 **停一下！** 观察（Observe）这步，为什么不能跳过？—— 设想你焯完排骨**不尝**就直接出锅上桌，排骨可能是生的。Agent 也一样：调了工具不看返回值，就不知道结果是正确还是错误。

---

## Agent Loop vs 普通聊天：到底差在哪

| | 普通聊天 | Agent Loop |
|---|---------|-----------|
| 流程 | 用户问 → AI 答（一次性） | 思考 → 行动 → 观察 → 再思考 → … |
| 能调工具吗 | ❌ 不能 | ✅ 能 |
| 做错了能改吗 | ❌ 不能，一次说完 | ✅ 能，观察后重新思考 |
| 像什么 | 投币贩卖机（塞钱出货） | 厨师做菜（边做边尝边调） |

💡 一句话：**普通聊天是"A→B 直达"，Agent Loop 是"A→B→C→A→B→…直到满足条件"。**

## 示范代码

一次最简单的 Agent Loop —— 用伪代码看清 Think → Act → Observe 三步怎么转。

```typescript
// ① 初始状态：用户说了句话
const userInput = "北京今天天气怎么样？";

// ② Think：模型自己决定下一步该干什么
const decision = await think(userInput);
// → "我需要查天气信息"

// ③ Act：执行刚才想的动作（假装查到了）
const observation = await act(decision);
// → { temp: 25, condition: "晴" }

// ④ Observe：看一眼结果——对吗？够了吗？
const isDone = observe(observation);
// → "结果正常，可以回答了"
if (isDone) {
  return "北京今天晴，25 度。";
}

// ⑤ 如果没做完（比如查天气失败、或者还要查第二件事）
// → 带着 observation 回到第 ② 步，再来一轮
// 这就是 Loop：Think → Act → Observe → Think → Act → Observe → ...
```

> 👉 **关于工具（`getWeather`）：** 上面 `act()` 里执行的动作，在真实项目中就是一个"工具"——查询天气的 API、搜索网页的函数、操作数据库的指令。**下一讲「工具调用」会详细说工具怎么写、怎么注册到 Agent 身上。** 这一讲你只需要理解：Agent 不是在"闲聊"，而是在**循环做决定**。

> 🛑 **关键检查：** 如果 `act()` 返回的不是天气数据，而是 `{ error: "城市不存在" }`——`observe()` 应该做什么？—— 发现结果是错的 → 回到 `think()` 重新决定下一步（"抱歉查不到这个城市"）。**这就是 Observe 的价值：发现错误，不是瞎说。**

---

## ⚠️ 常见误解

- 误解 1："Agent Loop 就是 while(true)" → ❌ 它是 LLM 在每一轮**重新决策**要不要继续，不是死循环。
- 误解 2："Agent 一次就能做对" → ❌ 一次调工具拿错参数 → Observe 发现错误 → 重新 Think → 再调。反复才是常态。
- 误解 3："观察就是看一眼" → ❌ 观察是**带着判断**看结果：结果对吗？还需要继续吗？出错了怎么办？
