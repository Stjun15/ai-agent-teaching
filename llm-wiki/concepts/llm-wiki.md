# LLM Wiki 知识编译

## 先来一个故事：编字典 vs 每次翻书

你有两种方式学英语：

- **方式 A**：每次遇到不认识的单词，去图书馆翻《牛津词典》→ 找到 → 抄下来 → 合上 → 下次遇到同一个词，又去图书馆翻一遍。
- **方式 B**：把常见的 3000 个单词整理成一本小字典，揣口袋里。遇到不认识的随时翻开看，不用再去图书馆。

**方式 A = RAG，方式 B = LLM Wiki。**

- RAG 是"每次现查"——成本高，但适合内容天天变的情况
- LLM Wiki 是"提前编译"——一次整理，后续每次直接翻口袋里的字典

> 🛑 **停一下！** 你现在能区分 RAG 和 LLM Wiki 吗？用一句话说：**RAG 是图书馆现查，LLM Wiki 是口袋里的字典。**

---

## RAG vs LLM Wiki：一张表终结所有混淆

| | RAG 📚 | LLM Wiki 📖 |
|---|---------|------------|
| **模式** | 解释器（边问边查） | 编译器（提前整理好） |
| **每次提问** | 重新检索原文 | 读已编译好的 Wiki 页面 |
| **知识积累** | 没有积累效应 | **有复利**：第100份资料建立在前面99份之上 |
| **成本** | 随提问次数线性增长 | 一次编译，持续复用 |
| **适合** | 新闻、实时数据 | 课程知识、公司规章、产品文档 |

---

## Wiki 的"复利效应"：为什么越用越值钱

想象你在编一本百科全书：

- 第 1 条知识"Python 变量"：修修补补写了一个小时
- 第 50 条知识"装饰器"：直接链接到"函数"、"闭包"——这些概念前面已经编译好了
- 第 100 条知识：建立在前面 99 条之上——你不需要重写"什么是函数"

**这就是复利效应：** 每一条新知识都建立在之前的知识结构之上，越到后面越省力。而 RAG 没有这个效应——每次都是从头检索。

## 三个核心操作

```
Ingest（摄入） → 把原始资料"编译"成结构化 Wiki 页面
Query（查询）   → 直接读 Wiki 页面回答，不重新检索原文
Maintain（维护） → 自动检查断链、标记矛盾、修复引用的死链接
```

## 示范代码

Wiki 三连 —— Ingest 编译 → Query 查询 → Maintain 维护。

> 👉 `wiki.ingest()` / `wiki.query()` / `wiki.maintain()` 都是封装好的函数——**你不需要看懂内部实现**。就像你用微波炉不需要懂磁控管原理一样。你只需要看懂：**传入什么 → 拿到什么 → 副作用是什么**。

```typescript
// ① 摄入：把原始资料编译成结构化 Wiki 页面
//    传入：原始文件 + 目标路径 + 模板名
//    拿回：无（副作用：磁盘上多了一个 .md 文件）
await wiki.ingest({
  source: "教学资料.pdf",           // 原始资料
  target: "concepts/agent-loop.md", // 编译后存到哪里
  schema: "教学概念",               // 用什么模板（定义+关键点+误解+相关概念）
});
// 背后做的事：读 PDF → LLM 编译成结构化 Markdown → 存到 target 路径

// ② 查询：直接读 Wiki 页面回答（不再检索原文）
//    传入：一个问题
//    拿回：基于 Wiki 页面的回答
const answer = await wiki.query("Agent Loop 有几步？");
// 背后做的事：读 concepts/agent-loop.md → 定位到「四步拆解」→ LLM 提取答案
// 成本：只读一个文件，不调 embedding 模型，不重新切片——比 RAG 快得多

// ③ 维护：自动检查 + 修复
//    传入：无
//    拿回：无（副作用：修复了能自动修的问题，标记了修不了的）
await wiki.maintain();
// 背后做的事：
//   a. [[agent-loop]] 链接的页面还存在吗？→ 不存在就标记"死链"
//   b. 前置概念列表和实际引用一致吗？→ 不一致就标记"矛盾"
//   c. 能自动修的修（死链重定向），不能修的标出来等人处理
```

> 🛑 **关键检查：** LLM Wiki 的 Query 和 RAG 的 retrieve 有什么区别？—— Wiki Query 直接读一个文件，RAG retrieve 要算向量相似度再找 top-K。**前者是"翻字典"，后者是"搜图书馆"。**

---

## ⚠️ 常见错误

- 错误 1：**把 LLM Wiki 当成"多存几个文件"** → 不只是存，关键是**结构化和交叉引用**。就像维基百科不只是文字——它有分类、链接、信息框。
- 错误 2：**Inbox 和 Wiki 搞混** → Inbox 是"资料先扔进去"，Wiki 是"整理好的知识"。先录入再编译。
- 错误 3：**以为 Wiki 编译完就万事大吉** → 知识会过时，交叉引用会断裂。不 Maintain 的 Wiki 是死 Wiki。
