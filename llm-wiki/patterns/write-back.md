# 结论回写知识库

## 什么时候用

一轮对话产生了**可复用的结论**（一个踩过的坑、一条被验证的写法）时，把它写成一页，而不是留在聊天记录里。

## 写法

```text
1. 判定：这条结论下次还会用到吗？（只用一次的，不写）
2. 定位：归到哪个目录、属于哪种页面类型
3. 落页：frontmatter 写全（type / last_updated / id），正文写「是什么 + 怎么用」
4. 交叉引用：用 [[wiki-link]] 连回相关概念，别让新页变成孤岛
5. 记日志：log.md 记一行「新增/修改了什么」
```

## 为什么有效

聊天记录是流式的、会过期；知识页是结构化的、能被检索。同一条结论，放在聊天里下次要靠人回忆，写成页下次检索就能命中 —— 检索命中率取决于页的**结构**（标题、类型、交叉引用），不取决于页的长度。

本项目里这个模式有具体后果：知识页最终会被 [[rag]] 那一层检索到，页面类型与 frontmatter 写错，检索就命中不了，写了等于没写。

## 容易退化成什么

- 退化成 [[token-explosion]]：什么都往里写，知识库变成垃圾场，检索噪声盖过信号；
- 退化成孤岛页：内容对，但没有任何 `[[wiki-link]]`，既连不回概念也进不了 `related` 检索范围。
