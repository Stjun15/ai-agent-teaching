# 角色契约四段

## 什么时候用

写 System Prompt 的时候。它是本项目点评 Agent 打分时第一个看的维度（实测维度名就叫「角色定义」）。

## 写法

四段，缺一段就会被扣分：

```text
你是一个 <身份>。

职责：<做什么，做到什么程度>。

风格：<怎么说，多长，用什么语气>。

边界：<不做什么，遇到什么情况停下来问>。
```

判据不是「写了多少字」，而是**这四段里有没有能被单独揪出来的信息**：

| 段   | 判据                            | 反面例子             |
| ---- | ------------------------------- | -------------------- |
| 身份 | 说清是什么角色，不是「AI 助手」 | "你是一个 AI"        |
| 职责 | 说清做什么，可验收              | "帮我解决问题"       |
| 风格 | 说清长度、格式、语气            | 不写，靠模型猜       |
| 边界 | 说清不做什么                    | "什么都行，你看着办" |

## 为什么有效

System Prompt 是**每次调用都会重发**的那一段。它越含糊，模型每次采样出的行为差异越大 —— 同一个问题得到两种风格，看起来像模型不稳定，实际是契约没写。

反过来说，四段写全之后，改行为只需要改其中一段，不用重写整篇。

## 容易退化成什么

- 退化成 [[weak-role-definition]]：只写身份不写职责与边界，模型只能自由发挥；
- 退化成身份堆砌："你是一个资深专家、顶级工程师、畅销书作者…" —— 头衔不是职责，见 [[vague-prompt]]。
