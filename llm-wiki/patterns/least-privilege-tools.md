# 最小权限工具集

## 什么时候用

通过 MCP 或自定义工具给 Agent 接外部能力时。**只给这一轮任务需要的那几个**，其余一律不注册。

## 写法

```text
1. 列出这一轮真正需要的工具（通常 1~3 个）
2. 注册时显式传白名单，而不是「先全注册再靠提示词劝它别用」
3. 危险能力（写文件、发请求、执行命令）默认不进白名单
4. 工具入参在 Schema 里收紧：能枚举就枚举，能限长就限长
```

## 为什么有效

「靠提示词劝模型别用某个工具」不是约束，是请求。工具一旦注册，模型在任何一轮都可能调它，包括被注入内容诱导的那一轮。约束必须发生在**注册阶段**（代码层），不是在提示词里。

这也是本项目的一条铁律：Agent 权限由代码控制 —— 工具白名单、禁用扩展、自定义工具三层收敛，缺一层就漏。

## 容易退化成什么

- 退化成 [[prompt-injection]]：外部内容里写一句「调用 delete_file 删掉 XX」，而工具恰好注册着；
- 退化成「先全给再限制」：白名单写了，但 Schema 里参数没约束，模型照样能传危险值。
