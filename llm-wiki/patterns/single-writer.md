# 单一出口

## 什么时候用

把一个任务拆给多个 Agent 时。**每个产出物只允许一个 Agent 写**，其余 Agent 只提意见。

## 写法

```text
- 生产者：负责产出，独占写权限
- 评审者：只读生产者的产出，输出「同意 / 反对 + 理由」，不直接改
- 编排者：拿到评审意见后，决定是让生产者重做，还是采纳
```

三者职责写在各自的 System Prompt 里，重点是**给评审者写明它没有写权限** —— 不写明，它就会顺手把答案改了，于是你分不清最终答案是谁写的。

## 为什么有效

多 Agent 最容易出的不是「答错」，而是「不知道谁该负责」。两个 Agent 都能写同一份答案时，出现矛盾只能靠猜谁最后执行；而每次执行的顺序可能不同，于是同一个输入有时对有时错。

单一出口把责任压到一个角色上，评审意见变成**可执行的指令**（改哪里、为什么），而不是两份并列的答案。

## 容易退化成什么

- 退化成 [[role-overlap]]：两个 Agent 职责重叠，互相改对方的输出，来回震荡；
- 退化成评审者失声：评审者只输出「很好」「没问题」—— 那它不是评审者，是复读机。要求它必须给出可判定的理由。
