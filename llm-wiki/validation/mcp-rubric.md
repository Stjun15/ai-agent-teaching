# MCP 评分标准

## 本模块动手题

1. 用"插座和插头"的例子，解释 MCP 协议为什么能"一次连接，到处可用"
2. 设计一个"本地文件管理"的 MCP Server：列出至少 3 个工具，每个写清 name、description、parameters

## 正确答案要点

### 概念解释
- 插座/插头比喻：MCP 是标准插座接口，任何符合标准的插头（工具Server）插上去就能用
- 一次连接到处可用：因为协议统一，不绑定具体工具实现

### MCP Server 设计
- 至少 3 个工具（如读文件、写文件、列出目录）
- 每个工具有：name（动词+名词）、description（用途+适用场景）、parameters（类型+必填）
- 参数描述具体（如 filePath: string, 必填）

## 维度与权重

| 维度       | 权重 | 评分要点                             |
| ---------- | ---- | ------------------------------------ |
| 工具设计   | 40%  | 至少 3 个工具、name/desc/params 完整  |
| 概念理解   | 30%  | 比喻恰当、解释了"为什么一次连接到处可用" |
| 实用性     | 20%  | 工具覆盖了文件管理核心操作           |
| 格式规范   | 10%  | 参照示范代码格式                     |

## 扣分规则

| 问题                     | 扣分  |
| ------------------------ | ----- |
| 少于 3 个工具            | -20   |
| 工具缺 description       | -10   |
| 工具缺 parameters        | -10   |
| 比喻没解释清楚           | -15   |
| name 不是动词+名词       | -5/个  |
| 参数缺少 required 标记   | -5/个  |

## 通过条件

- total_score >= 75
- 至少 3 个工具且有完整 name/description/parameters
- 概念理解正确
