# LLM API 评分标准

## 本模块动手题

1. 用"餐厅后厨"的例子解释什么是 LLM API
2. 回答：为什么 AI 看起来"记得"上一句，但实际上不记得？
3. 写出一个 `messages` 数组：system prompt 为"你是高中数学老师，回答要严谨、有推导过程"，user 消息为"请用三种方法证明勾股定理"

## 正确答案要点

### 概念解释部分
- 用后厨比喻：你是顾客（用户），服务员是 API，后厨是模型
- 核心：每次调用是"全新的一次"，历史对话靠 messages 数组传递

### 代码部分
- `role` 字段正确（"system" / "user"）
- `content` 写清楚、完整
- 语法正确（逗号、引号都对）

## 维度与权重

| 维度       | 权重 | 评分要点                             |
| ---------- | ---- | ------------------------------------ |
| 理解准确度 | 35%  | API 概念理解正确、"7秒记忆"机制说清   |
| 比喻质量   | 20%  | 后厨比喻恰当、层次清楚               |
| 代码正确性 | 30%  | role/content/语法全对                 |
| 完整覆盖   | 15%  | 两问 + 代码都完成                    |

## 扣分规则

| 问题                     | 扣分  |
| ------------------------ | ----- |
| 混淆 API 和模型          | -20   |
| 说"AI有记忆"            | -20   |
| role 写错（如 system 写成 sys） | -15   |
| content 空或太简         | -10   |
| 语法错误（缺逗号/引号）  | -5/处 |
| 比喻不用后厨            | -5    |

## 通过条件

- total_score >= 75
- 理解准确度 >= 60% 权重分
- messages 数组语法正确
