# RAG 评分标准

## 本模块动手题

1. 用"图书馆查书"的例子，解释 RAG 的三步：检索 → 增强 → 生成
2. 回答：RAG 和 LLM Wiki 最大的区别是什么？什么情况用哪个？
3. 仿照示范代码写出宠物店知识库（grooming.md / adopt.md / price.md）
4. 回答：用户问"领养需要几天？"时 buildContext() 拼出什么内容？

## 正确答案要点

### 概念解释
- 图书馆比喻贯穿三步：查目录=检索 → 取书=增强 → 翻书写答案=生成
- RAG vs Wiki 区别：RAG 是"现查现用"（每次重新检索），Wiki 是"先整理后用"（一次编译反复用）
- 资料经常变用 RAG，资料稳定用 Wiki

### 知识库代码
- knowledgeBase 格式与示范代码一致：`{ doc, source }` 结构
- 三篇文档内容正确：美容预约、领养流程、价目表
- 语法正确

### buildContext 输出预测
- adopt.md 排第一（与"领养"最相关）
- 正确预测输出格式：[资料N] 来源 → 内容
- 指出 AI 从 adopt.md 找到"试养3天"

## 维度与权重

| 维度       | 权重 | 评分要点                             |
| ---------- | ---- | ------------------------------------ |
| 理解准确度 | 35%  | RAG 三步理解正确、RAG vs Wiki 区分清  |
| 代码正确性 | 30%  | knowledgeBase 格式/内容/语法都对      |
| 推理能力   | 20%  | buildContext 输出预测逻辑正确         |
| 完整覆盖   | 15%  | 四问都答了                           |

## 扣分规则

| 问题                     | 扣分  |
| ------------------------ | ----- |
| 混淆 RAG 和 Wiki 的区别  | -20   |
| 知识库格式不对（缺 source 或 doc） | -15   |
| 三篇文档少了一篇         | -10   |
| buildContext 排序错误     | -10   |
| 语法错误                 | -5/处 |
| 没用自己的话说           | -5    |

## 通过条件

- total_score >= 75
- 理解准确度 >= 60% 权重分
- knowledgeBase 格式正确
