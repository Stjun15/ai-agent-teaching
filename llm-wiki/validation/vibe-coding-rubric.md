# Vibe Coding 评分标准

## 本模块动手题

学生为一个小项目写四步策划书（`.md` 文件），并用 Git 全程存档。

策划书包含四步：
1. 说清楚（目标、上下文、约束、完成条件）
2. 定规矩（至少三条）
3. 切小块（至少 4 个任务，每个可独立验证）
4. 回头看（验证计划）

Git 存档：`git log --oneline` 输出，commit 数 ≥ 任务数，message 有意义。

**学生不写代码。交的是策划文档 + Git 记录。**

## 正确答案要点

### 四步完整
- 每一步有对应的段落内容，不是只写标题
- 步四不能是"我会检查"四个字——必须有具体的验证方式

### 完成条件可判对错
- 每条完成条件能用"是/否"回答
- 不能出现"好看""好用""流畅"等模糊词
- 正确示例："页面能打开并显示本周 7 天"、"勾选后刷新页面不丢失状态"

### Git 记录
- `git log --oneline` 行数 ≥ 步三拆出的任务数
- 每条 commit message 不是 "update"、"fix" 这类空话
- 能看出每次提交对应哪个任务

## 维度与权重

| 维度 | 权重 | 评分要点 |
|---|---|---|
| 四步完整 | 40% | 每一步有实质性内容，步四有具体验证方式 |
| 条件可判 | 30% | 完成条件都是可判对错的，无模糊词 |
| Git 规范 | 15% | commit 数够、message 有意义 |
| 表达清晰 | 15% | 策划书条理分明、一人能看懂 |

## 扣分规则

| 问题 | 扣分 |
|---|---|
| 四步缺一步 | -20 |
| 步四只写"我会检查"四个字 | -15 |
| 完成条件用了模糊词（好看/好用/流畅） | -10/条 |
| 步三任务不够 4 个 | -10 |
| Git log 行数不够 | -10 |
| commit message 是 "update" / "fix" | -5/条 |
| 步二规矩不够三条 | -10 |
| 没有 Git 记录 | -15 |

## 通过条件

- total_score >= 75
- 四步完整（四步都有实质性内容）
- 完成条件无模糊词
