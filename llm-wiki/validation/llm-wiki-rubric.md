# LLM Wiki 评分标准

## 本模块动手题

1. 用"编字典"的例子，解释 LLM Wiki 和 RAG 的区别
2. 回答：什么叫"复利效应"？为什么第 100 条知识编译起来比第 1 条快？
3. 写一条 `wiki.ingest()` 调用，把《考勤政策.pdf》编译进 Wiki（source / target / schema 三个参数）
4. 描述 `wiki.query("加班怎么算调休？")` 的行为：读哪个文件？为什么能快速定位？

## 正确答案要点

### 概念解释
- 编字典比喻：Wiki 是"把精华编成百科词典随身带"，RAG 是"每次去图书馆现查"
- 复利效应：前 99 条已经建立了结构和关联，第 100 条只是对号入座，不重新建立框架

### 代码部分
- source: 原始文件路径（考勤政策.pdf）
- target: 编译后的 Wiki 条目名
- schema: 结构化模板（如时段/规则/条件/处理方式）
- 三个参数都写对

### query 行为描述
- 会读编译后的考勤政策 Wiki 条目
- 快速定位原因是：已结构化（schema），直接匹配"加班→调休"字段，不需要全文扫描

## 维度与权重

| 维度       | 权重 | 评分要点                             |
| ---------- | ---- | ------------------------------------ |
| 理解准确度 | 35%  | Wiki vs RAG 区分清、复利效应理解正确  |
| 代码正确性 | 30%  | source/target/schema 三参数完整正确   |
| 推理能力   | 20%  | query 行为描述逻辑正确                |
| 完整覆盖   | 15%  | 四问 + 比喻都完成                    |

## 扣分规则

| 问题                     | 扣分  |
| ------------------------ | ----- |
| Wiki vs RAG 说反         | -20   |
| 复利效应解释错误         | -15   |
| ingest 参数少一个        | -10   |
| schema 太模糊（如"结构化"没说清） | -10   |
| query 行为描述错误       | -15   |

## 通过条件

- total_score >= 75
- 理解准确度 >= 60% 权重分
- ingest 三个参数完整
