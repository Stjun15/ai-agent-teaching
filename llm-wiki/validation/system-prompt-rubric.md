# System Prompt 评分标准

## 本模块动手题

1. 用"入职说明书"的比喻解释 System Prompt 三个维度的作用
2. 设计一个「奶茶店点单助手」的 System Prompt，必须包含角色、格式、边界三个维度，每个维度至少两行

## 正确答案要点

### 比喻解释部分
- 角色 = 岗位名称（做什么的）
- 格式 = 工作流程（怎么做）
- 边界 = 权限范围（什么不能做）

### 奶茶店点单助手部分
- 角色：至少两行，说明身份（店员/助手）、语气（亲切）、职责（只点单不聊天）
- 格式：至少两行，说明输出什么格式（清单）、多长（简洁不啰嗦）
- 边界：至少两行，遇到不知道的口味怎么办、客人要投诉怎么办

## 维度与权重

| 维度     | 权重 | 评分要点                         |
| -------- | ---- | -------------------------------- |
| 角色定义 | 30%  | 身份清晰、职责明确、能力边界清楚 |
| 输出格式 | 25%  | 结构化、字段明确、长度控制       |
| 边界条件 | 25%  | 异常场景、兜底策略、拒绝方式     |
| 表达     | 20%  | 比喻恰当、逻辑通顺、无矛盾       |

## 扣分规则

| 问题                 | 扣分  |
| -------------------- | ----- |
| 三个维度缺一个       | -20   |
| 某个维度不足两行     | -10   |
| 角色定义模糊（如"你是助手"） | -15   |
| 边界用例编造（如说"拒绝回答恶意问题"太笼统） | -10   |
| 格式缺少具体示例     | -10   |
| 比喻解释张冠李戴     | -15   |

## 通过条件

- total_score >= 75
- 角色定义 >= 60% 权重分
- 三个维度必须全部覆盖
