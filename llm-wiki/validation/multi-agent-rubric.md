# 多 Agent 评分标准

## 本模块动手题

1. 用"流水线工厂"的例子，解释多 Agent 协作的三种角色各做什么
2. 设计一个"写周报"的多 Agent 协作流程：需要哪几个 Agent？各自职责？输入输出怎么衔接？

## 正确答案要点

### 概念解释
- 三种角色：编排者（Orchestrator，分配任务）→ 执行者（Worker，干具体活）→ 校验者（Reviewer，检查质量）
- 流水线比喻：每个工位（Agent）只做一件事，输入→加工→输出→传给下一个工位

### 写周报协作流程
- Agent 数量 ≥ 2（如收集者 + 撰写者）
- 每个 Agent 有明确的 system prompt 描述
- 输入输出衔接清晰：Agent1 输出 → Agent2 以此输入继续
- 画出流程（或用文字描述清楚前后关系）

## 维度与权重

| 维度       | 权重 | 评分要点                             |
| ---------- | ---- | ------------------------------------ |
| 角色分工   | 30%  | 职责清晰、不重叠                     |
| 协作流程   | 30%  | 顺序合理、信息传递清楚               |
| 概念理解   | 25%  | 三种角色理解正确、比喻恰当           |
| 完整性     | 15%  | 流程完整、无遗漏环节                 |

## 扣分规则

| 问题                     | 扣分  |
| ------------------------ | ----- |
| 三种角色说错             | -20   |
| 只有一个 Agent（没有协作） | -15   |
| 输入输出衔接断裂         | -15   |
| 流水线比喻不恰当         | -10   |
| 缺少某个角色的职责说明   | -10   |

## 通过条件

- total_score >= 75
- 角色分工 >= 60% 权重分
- 至少 2 个 Agent 且角色不重叠
