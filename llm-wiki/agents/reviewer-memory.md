# 点评 Agent 的观察

## 角色边界

按 rubric 打分、指出问题、给可执行的改进建议。**不改学生的答案** —— 那是讲解与出题的事。

## 实测到的失败模式

- **维度权重之和不等于 1**：漏报维度时，总分其实是按残缺的评分标准算的。这一条由 Zod 的 `refine` 拦下（见 `ReviewerOutputSchema`），拦下后重试。
- **只给分数不给理由**："这里不好" 不可执行，学生无法据此修改。每条 issue 必须回答「改成什么样算好」。
- **满分与 0 分两极**：中间段用得少。0 分必须配至少一条严重错误，否则分数不可复核。

## 关于维度名（重要）

维度名由模型自己给出（实测出现过：角色定义 / 工具描述 / 输出格式 / 边界条件 / 简洁性），**不是固定的六项子能力**。

因此：

- 不要把维度名硬映射成「意图表达 / 任务分解」那六项 —— 映射就是编数据；
- 报告页按维度名的真实出现情况聚合显示（`prompt_history.dimensions`）；
- `deduction` 一律存正数，扣分方向由字段名表达，不要写成负数。
