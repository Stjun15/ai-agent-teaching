## 一、项目概述

### 1.1 解决什么问题

想真正掌握 AI 协作能力的学习者，缺少「从概念到能跑通的 Agent 项目」之间的训练路径。市面上的教程要么只讲模型 API 的调用参数，要么直接给一份能跑的现成代码——中间最关键的一截被跳过了：**怎么把模糊意图变成可靠的结构化指令、怎么让 AI 稳定干活、怎么判断 AI 的产出可不可信**。这三件事恰恰是使用 AI 的人每天真正在做的事。

本项目是一个 **AI Native 编程教学助手**：一个面向零基础学习者的 Web 应用，用 12 讲课程把九个 AI 工程模块（API → 提示词 → Agent Loop → 工具调用 → RAG → 知识库 → 多 Agent → MCP → 安全）教完，最终以「复刻一个教学平台」作为毕业课题。它训练的不是「让 AI 替你写完代码」，而是六项可迁移的 AI 协作能力：

| 子能力     | 含义                                       |
| ---------- | ------------------------------------------ |
| 意图表达   | 把想法变成清晰、无歧义的自然语言           |
| 上下文构建 | 知道 AI 需要什么背景信息，并主动供给       |
| 任务拆解   | 把大任务切成 AI 一次能可靠完成的小步       |
| 结果校验   | 判断 AI 输出是否正确、是否在胡编           |
| 迭代修正   | 根据校验结果给出可执行的修正指令           |
| 安全边界   | 知道哪些事不该交给 AI、哪些风险要防        |

### 1.2 与「又一个聊天框」的本质区别

本产品的核心差异点是一条**用 Agent 教 Agent 的闭环**：

- **界面内**，四个各司其职的 AI Agent（讲解 / 点评 / 出题 / 答疑）驱动七步教学流程（讲解 → 示范 → 模仿 → 点评 → 可视化 → 练习 → 掌握判定），每一步都有对应的权限约束、评分维度与数据库落地；
- **界面外**，一个自动化学生 Agent 能代替人类学生**从第一讲学到最后一讲并毕业**——课程质量因此从主观判断变成了**可反复执行的命令**：12 讲全链路模拟（约 80 次真实模型调用）全部通过、解锁链零断裂，判分误判、掌握度断裂、材料缺口都是被这个学生 Agent 抓出来再修掉的。

这个闭环本身就是作品最大的创新点：**我们用被教的方法（Agent 编排）来保证教的内容（课程质量）**。

### 1.3 作品形态

纯 Web 应用（Next.js 16 App Router，React 19 + TypeScript），浏览器访问即用。后端仅承担 AI 能力接入（Agent 编排、模型调用、教学数据落库），没有任何「为后端而后端」的模块——27 个 API 端点每一个都能指到它服务的界面。

关键数字（2026-09-30 实测）：

| 项                  | 数值                                                        |
| ------------------- | ----------------------------------------------------------- |
| 课程                | 12 讲（2 讲语言速通 + 9 个 AI 工程模块 + 1 个复刻毕业课题） |
| 教学 Agent          | 4 个（讲解 / 点评 / 出题 / 答疑）× 7 个技能                 |
| 编排循环            | 4 个（教学 / 出题 / 点评 / 判分）                           |
| 可视化场景          | 9 个（每个 AI 工程模块一个，可交互播放）                    |
| API 端点            | 27 个（全部 Zod 契约校验）                                  |
| 数据表              | 18 张（含真实教学流量：375 条调用轨迹、130 条点评记录）     |
| 测试                | 36 组（33 纯函数/DB + 3 组真实模型回归），全绿              |
| 知识库              | `llm-wiki/` 66 个 Markdown 页面，唯一内容事实源             |

## 二、需求分析

### 2.1 目标用户与真实场景

目标用户是**零基础的 AI 协作学习者**：高职学生、刚入行的开发者、想把 AI 用进自己专业的人。他们的真实困境不是「没有教程」，而是三个具体的坎：

1. **学了概念不会用**——知道什么是 RAG，但不知道在自己遇到的问题里该怎么组装；
2. **AI 的输出没法判断对错**——模型说得头头是道，但不知道哪句是真会、哪句是在编；
3. **反馈缺失**——写完一段 Prompt、交完一份作业，没人告诉哪里好、哪里差、下一步练什么。

传统解法是「人教」：助教批改、老师答疑。这在规模上不可持续。本项目的解法是把「教、评、练、测」四个环节全部 Agent 化，且**每个环节的判断标准都写死在代码里**，不依赖模型措辞。

### 2.2 需求到功能的映射

| 真实需求                     | 对应功能                                                             | 服务的能力训练 |
| ---------------------------- | -------------------------------------------------------------------- | -------------- |
| 概念看不懂                   | 讲解 Agent 分步讲解 + 提问追问（流式输出，点开即有）                  | 意图表达       |
| 不知道正确做法长什么样       | 示范步：讲稿代码提取 + 分屏展示，确认后进入模仿                       | 上下文构建     |
| 想动手但怕写错               | 模仿步：任务卡明确「现在轮到你」，Monaco 编辑器内完成                  | 任务拆解       |
| 交了作业没反馈               | 点评 Agent 按维度打分 + 扣分问题清单 + 改进建议（真实落库）            | 结果校验       |
| 抽象概念看不见               | 9 个可视化场景：请求流、Agent 循环、检索管线、攻击-防护对比可交互播放 | 意图表达       |
| 练习不够、难度不匹配         | 出题 Agent 按掌握度定难度起点，变式练习 + 主/客观题判分                | 迭代修正       |
| 学了就忘、不知道下一步学什么 | 掌握度引擎 + 学习路径调整建议（基于下降、连续失败、错题积压）          | 任务拆解       |
| 作业截图不会描述             | 多模态点评：上传截图（≤3 张，自动压缩），视觉模型独立点评管线          | 结果校验       |

### 2.3 赛题约束的落实

赛题明确「以前端 Web 应用为主要呈现形态，后端服务仅作为 AI 能力的接入层」。本项目把它转化为一条可检验的架构自检标准：**没有为后端而存在的模块**。所有 API 端点都是某个界面的直接供给（数据获取、教学动作、流式回答），不存在报表后台、批处理任务这类「后端为其自身」的功能。模型调用、编排循环虽然运行在服务端，但它们是「AI 能力接入层」本身——前端应用的主要交互（七步教学、对话、可视化、报告）全部在浏览器完成。

### 2.4 与同类产品的对比

| 维度         | 通用 AI 聊天产品 | 视频课程平台 | 本项目                         |
| ------------ | ---------------- | ------------ | ------------------------------ |
| 教学判断     | 无               | 人工出题批改 | Agent 点评 + 代码写死的通过线  |
| 个性化       | 靠用户自己问     | 无           | 掌握度引擎驱动难度与路径       |
| 内容可信     | 无法保证         | 制作周期长   | 知识库是唯一事实源，可评审可 diff |
| 质量验证     | 无               | 无           | 学生 Agent 全链路模拟 12/12    |
| 反馈闭环     | 无               | 弱           | 错题本 + 提示词历史 + 学情报告 |

## 三、系统架构设计

### 3.1 六层结构

| 层         | 职责                                 | 代码位置                                                  | 硬约束                                 |
| ---------- | ------------------------------------ | --------------------------------------------------------- | -------------------------------------- |
| 呈现层     | 页面、组件、9 个可视化场景           | `src/app/**`、`src/components`、`src/scenes`              | 服务端组件可读文件系统，客户端组件不行 |
| 接入层     | HTTP 契约、身份、校验、限流          | `src/app/api/**`（27 个路由）                             | **只有这里知道「这是谁」**             |
| 编排层     | 何时调用哪个 Agent、重试与降难度     | `src/lib/agent/orchestrator`（4 个循环）                  | 不碰 HTTP、不构造身份                  |
| Agent 内核 | 提示词组装、模型调用、校验兜底、观测 | `src/lib/agent/{runtime,loop,prompts,skills,tools,trace}` | 想调模型必须过 `runAgent`              |
| 知识层     | 教学内容的权威来源                   | `llm-wiki/`（66 页 Markdown）+ `src/wiki`（解析与检索）   | 改内容只改 Markdown，不改代码          |
| 数据层     | 表与仓库                             | `src/lib/db`（18 张表，按表拆分仓库）                     | 驱动名只允许出现在 `sqlite.ts`         |

三条最重要的边界：

1. **身份只在接入层构造**——编排层与内核只透传学生身份，不存在「在编排层硬凑上下文」导致的归属错误。
2. **模型调用只有一个入口**（`runAgent`）——trace 记录、输出打码、技能越权检查全部挂在这一个出口上，所以不存在「某个端点漏了」这种漏法。
3. **知识层是文件而不是数据库**——12 讲的 id、名称、难度、前置依赖全部从 Markdown frontmatter 现读，教学顺序由前置依赖拓扑排序自动得出。

### 3.2 技术选型（前端为主体）

| 项        | 选择                                          | 选型理由                                                                 |
| --------- | --------------------------------------------- | ------------------------------------------------------------------------ |
| 框架      | Next.js 16（App Router + Turbopack）+ React 19 | 赛道推荐首选：Server Components 读知识库文件、API Routes 做 AI 接入、流式渲染 |
| 语言      | TypeScript（`tsc --noEmit` 进门禁）           | 类型即契约：Agent 枚举、StepType 都是「活断言」，删一个值编译就报错        |
| 样式      | Tailwind CSS 4 + shadcn/ui（Radix 原语）      | 赛道强烈推荐组合；设计系统统一                                            |
| 状态      | Zustand                                       | 轻量；主题偏好、学生档案 hydration 走 bootstrap 组件                      |
| 流式      | SSE（逐 token 推送）                          | AI 流式回答的标准路径；配合批量合并渲染（见 4.6）                          |
| 数据库    | 开发期 `node:sqlite`（零依赖免原生编译）      | 部署期换托管库时只改一个驱动文件                                          |
| 编辑器    | Monaco                                        | 沙箱与代码点评的编辑体验                                                  |
| 质量门禁  | ESLint + Prettier + tsc 一条命令              | CI 可跑的统一门禁                                                         |

### 3.3 数据模型

18 张表分五组：教学主链路（会话、消息、题目、答题结果）、学情（掌握度、学习路径、学生画像、学生）、点评与观测（点评结果、调用轨迹、提示词历史、错题）、讲稿缓存、鉴权（用户凭证）。两层设计决策值得说明：

- **掌握度表是引擎的脊柱**：每讲一张行，分数 0-5。正式测评是「覆盖更新」（最新测量反映现状），练习是「只升不降」（练错一道题不该把已通过的掌握度砸回去、把已解锁的后续模块重新锁死）——这条语义是从全链路模拟实测出的连锁后果里定下的。
- **讲稿缓存表**：9 模块 × 讲解/示范的讲稿预生成落库，学生点开讲解步零等待显示；未命中回退实时生成。提示词或模型升级后一条命令重建。

### 3.4 部署形态

生产构建（`next build`）+ Node 服务常驻，SQLite 单文件库随应用走，nginx 反代时对 SSE 关闭缓冲。仓库 `deploy/` 内含一键部署脚本与说明。数据库层做了驱动隔离，换托管 PostgreSQL 是配置级改动。

## 四、AI 技术方案

### 4.1 模型选型理由

| 用途     | 模型                        | 选型理由                                                             |
| -------- | --------------------------- | -------------------------------------------------------------------- |
| 文本主力 | DeepSeek（火山方舟端点）    | 中文教学质量好、成本低（教学场景调用量大）；OpenAI 兼容端点便于切换    |
| 视觉点评 | Doubao 视觉理解模型（方舟） | 学生作业截图的读图与点评；与文本模型同平台，密钥与网关统一            |

接入层统一走火山方舟的 OpenAI 兼容端点，provider 配置收敛在一个文件里（`ark.ts`）：模型名、端点、密钥三处口径同源。选型上刻意不绑死单一厂商——换模型只改配置，提示词与编排层不动。教训也写进了流程：每次换模型端点名，必须先 curl 验证端点存在，再改代码、再跑真模型回归。

### 4.2 四层执行架构：让 Agent 可控

「接一个模型做问答」谁都会；难的是让 AI 在教学场景里**每一步都做对的事、说出格式正确的产出**。本项目的答案是四层执行架构：

| 层       | 载体          | 内容                                       |
| -------- | ------------- | ------------------------------------------ |
| 1 身份层 | System Prompt | Agent 是谁、职责、行为准则                 |
| 2 技能层 | Skill 定义    | 具体任务怎么做（步骤、评分维度、通过条件） |
| 3 知识层 | LLM Wiki      | 概念、反模式、评分标准、学生画像           |
| 4 编排层 | 工作流代码    | 什么时候调用谁、读哪些页面、失败怎么办     |

组装点在 `composeAgentPrompt`：身份层与技能层拼成 system prompt，情境数据单独走用户消息——技能进 system prompt 而不是用户消息，是为了让「怎么做」不随每一轮输入漂移。

### 4.3 Agent 与工作流设计（权限由代码控制）

四个 Agent × 七个技能，**权限写死在代码里，不靠模型自觉**：

| Agent      | 职责                 | 允许使用的技能                                                               |
| ---------- | -------------------- | ---------------------------------------------------------------------------- |
| 讲解 Agent | 概念讲解、答疑       | `explain-concept`、`trigger-visualization`、`answer-question`                |
| 点评 Agent | 作业点评、代码校验   | `validate-prompt`、`validate-tool`、`validate-code`、`trigger-visualization` |
| 出题 Agent | 变式练习出题         | `generate-question`                                                          |
| 答疑 Agent | 自由提问             | `answer-question`、`explain-concept`                                         |

三层收敛，缺一层就漏：**技能白名单**（`allowedSkills` 之外的技能在入口直接抛错、根本不发给模型）+ **工具总白名单**（SDK 的 `tools` 字段同时过滤内置与自定义工具）+ **结构约束**（真正干活的 `executeAgent` 不导出，绕过它就跳过了权限检查）。

四个编排循环各司其职：教学循环（按学习阶段分派讲解/练习/校验）、出题循环（模块级调用，按掌握度定难度起点）、点评循环（作业 → 维度分 + 问题清单 + 是否通过）、判分循环（客观题走规则判分不调模型，主观题复用点评 Agent）。

一条关键设计：**通过线是代码写死的硬条件，不依赖模型措辞**。模型说「很好、很棒」不构成通过——模型只提供维度分与问题清单，「过不过」由代码判定。这从机制上消灭了「其实没过却被判过」。

### 4.4 结构化输出：JSON + Zod 逐次校验

模型输出全部要求 JSON，并逐次跑 Zod 校验：

- **校验**：每次尝试都解析 JSON 并按该 Agent 的 schema 校验；
- **重试**：失败时把 Zod 报错与模型原话回填给模型，让它知道错在哪——字段级错误回喂，而不是笼统的「格式不对」；
- **上限**：最多 3 次尝试，token 按尝试累加（重试是真实成本，调用轨迹里看得到「这次花了三次才过」）；
- **兜底**：三次都不合法则走兜底并打上 `usedFallback` 标记。

兜底有两条硬原则：**诚实**（必须能被识别，文案写明「本次自动评分未生效」）与**不阻断**（给学生继续走的方向）。评分兜底刻意给「未评分」而不是假分数——给一个看起来像正常评分的假分数，是最坏的一种兜底。

### 4.5 检索增强（RAG 形态的诚实说明）

讲解与答疑的回答**不是裸调模型**：先在本地知识库（66 页 Markdown）做检索，把命中的知识页作为上下文注入，回答带引用。检索是**加权关键词检索**，不是向量检索——这是明说的架构取舍：

- 打分 = 字段权重 × 命中次数 + 短语奖励；低于相关度门槛的命中直接丢弃（一个常用词就能让几十页过线，全发给学生是噪音）；
- **为什么不用向量检索**：教学内容是人工精写的 Markdown，页数少、结构强、术语密度高，关键词检索的命中率足够，且省掉 embedding 管线与向量库的部署重量；知识库可评审、可 diff、可版本管理，这是教学内容最需要的性质；
- **升级路径已预留**：数据库层驱动隔离，换托管 PostgreSQL + pgvector 是代码级改造而非重构。

引用在模型回答**之前**以 SSE 事件发给前端：检索是毫秒级的，学生先看到「本节参考了哪几页」，再看到逐字生成的答案——等第一个 token 的空档不被浪费。

### 4.6 前端 AI 交互的优化策略（SSE 三层管线）

AI 回答的流式体验是逐 token 的 SSE 推送与 React 渲染之间的工程问题。原始实现每个 token 触发一次 `setState`，30-80 次/秒的重渲染让对话卡死。三轮优化后的管线：

1. **Token 批量合并**：token 先进缓冲区，一个渲染 tick 内合并刷新，渲染频率从 30-80 次/秒降到约 20 次/秒——数据流语义（SSE 逐帧）与渲染性能（React 批量）之间的桥梁；
2. **引用检索与会话创建并行**：首字节前的串行空等（2-5 秒）消除，引用、思维链先于正文到达；
3. **思维链先于首 token 可见**：模型的思考过程默认展开、逐段追加，学生看得见 AI「怎么想」——这本身就是教学的一部分。

### 4.7 多模态能力

学生可以把作业截图直接拖进对话（最多 3 张，PNG/JPEG/WebP，前端自动压缩到尺寸上限）。接入层检测到图片即切换到**视觉模型独立点评管线**：不走文本 Agent 的提示词组装，而是按图片点评的任务结构单独组装——点评维度、输出 schema、兜底行为与文本点评对齐。这条管线让「我不会描述我的问题」不再是门槛：截图就是提问。

### 4.8 工具集成与安全

**工具调用**：Agent 通过 SDK 的工具协议（Function Calling 语义）调用外部工具，工具参数用 TypeBox 声明 schema、运行时校验；工具白名单与技能白名单双层过滤。可视化场景把「工具调用链」「Agent Loop 请求-响应」「MCP 调用流程」做成可交互的动态演示——工具如何被声明、如何被模型选择、结果如何回填，全部可视。

**安全四道门**：

| 门       | 位置                       | 拦什么                                                             |
| -------- | -------------------------- | ------------------------------------------------------------------ |
| 输入过滤 | 对话路径第一站             | 提示注入（危险指令、越权角色扮演、套取系统提示词）；拦下的输入不落库 |
| 输出打码 | `runAgent` 出口，递归遍历  | 凭据形态（密钥前缀、Bearer 令牌），按结构性模式识别                 |
| 限流     | 每个受限端点第一行         | 误刷与脚本循环（进程内固定窗口）                                    |
| 权限     | `runAgent` 入口            | 技能与工具的越权调用                                                |

两处刻意的「不拦」同样是设计：作业提交路径不过滤（安全模块的作业本身就是写攻击样例，拦了学生没法交作业）；演示场景的过滤规则与真实模块**引用同一份代码**（有测试钉住）——否则就是在演安全，不是讲安全。

**鉴权**：密码 scrypt 哈希 + JWT 签名验证（HS256、7 天有效期），注册/登录/改密三个端点 + 前端登录门。API 密钥只经环境变量注入，不入库、不出现在任何公开文件。

## 五、核心功能实现

### 5.1 七步教学流程（分屏式）

每讲七步：**讲解 → 示范 → 模仿 → 点评 → 可视化 → 练习 → 掌握判定**，步骤 id 是数据库契约（`StepType`），不是界面自定。三步分屏是核心交互设计：

- **讲解步**：讲解 Agent 按该讲的知识页裁剪注入（定义/关键点/为什么/对比），讲稿预生成进缓存表，点开即有、零等待；学生可提问追问，答疑流式回答带知识库引用。
- **示范步**：示范卡直接从知识页的「示范代码」节提取带逐行中文注释的可运行代码——**零模型调用**，内容永远与知识库一致；确认理解后门控跳转。
- **模仿步**：任务卡写明「现在轮到你」，学生在 Monaco 编辑器完成作业并提交，点评 Agent 按维度打分。

聊天按步骤过滤，不串内容；跨模块会话隔离有事件守卫（修过实际串台 bug）。

### 5.2 点评闭环与学情落地

提交点评后，系统真实地做四件事：建会话 → 调点评 Agent（携带题面与维度标准）→ 结果落库（点评结果、提示词历史、不通过时错题）→ 报告页展示维度分、扣分问题、改进建议。客观题走规则判分（答对判 0 分的历史 bug 已修并有守卫），判分解析随错题入库。**兜底输出一律不写库**——编的失败不是学生的失败。

报告页聚合三块真实数据：错题本（含「解析：」出处标注）、提示词历史（每次真实点评一行）、评分维度雷达。薄弱点直接由点评流量点亮，没有任何占位假数据。

### 5.3 掌握度引擎与自适应路径

- **掌握度更新语义**：正式测评覆盖更新（最新测量反映现状）；练习只升不降（防止练错一题砸碎已解锁的进度链）；客观题单题判分不更新掌握度（0/100 映射 0/5 会大幅摆动），信号进错题本。
- **路径调整**：规则引擎基于掌握度下降、连续失败、错题积压自动生成学习路径调整建议，模块页与报告页复用同一组件展示。
- **出题难度自适应**：出题 Agent 读掌握度定难度起点，答案形态约束随题面下发给前端。

### 5.4 可视化场景（9 个）

每个 AI 工程模块配一个可交互的动态场景：请求-响应流程、角色滤镜对比、Agent 循环（天气查询）、工具调用链、检索-生成管线、RAG vs 知识库对比、多 Agent 通信、MCP 调用流程、攻击-防护对比。场景数据（`.ts`）与视觉（`.tsx`）分离——数据文件被测试直接 import 断言（17 例场景断言），视觉层只管渲染。

### 5.5 讲稿缓存（点开即有）

讲解/示范讲稿按「9 模块 × 步骤」预生成落库（21 份），提示词、开场词、模型三处口径与运行时同源（守卫测试钉住）。模型或提示词升级后一条命令重建全部缓存，单页微调支持按模块步骤精准覆盖。学生侧效果：讲解步零等待，冷启动也有知识页正文兜底。
