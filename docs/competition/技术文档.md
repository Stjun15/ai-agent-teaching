## 一、项目概述

### 1.1 解决什么问题

想真正掌握 AI 协作能力的学习者，缺少「从概念到能跑通的 Agent 项目」之间的训练路径。市面上的教程要么只讲模型 API 的调用参数，要么直接给一份能跑的现成代码——中间最关键的一截被跳过了：**怎么把模糊意图变成可靠的结构化指令、怎么让 AI 稳定干活、怎么判断 AI 的产出可不可信**。这三件事恰恰是使用 AI 的人每天真正在做的事。

本项目是一个 **AI Native 编程教学助手**：一个面向零基础学习者的 Web 应用，用 12 讲课程把九个 AI 工程模块（API → 提示词 → Agent Loop → 工具调用 → RAG → 知识库 → 多 Agent → MCP → 安全）教完，最终以「复刻一个教学平台」作为毕业课题。它训练的不是「让 AI 替你写完代码」，而是六项可迁移的 AI 协作能力：

| 子能力     | 含义                                       |
| ---------- | ------------------------------------------ |
| 意图表达   | 把想法变成清晰、无歧义的自然语言           |
| 上下文构建 | 知道 AI 需要什么背景信息，并主动供给       |
| 任务拆解   | 把大任务切成 AI 一次能可靠完成的小步       |
| 结果校验   | 判断 AI 输出是否正确、是否在胡编           |
| 迭代修正   | 根据校验结果给出可执行的修正指令           |
| 安全边界   | 知道哪些事不该交给 AI、哪些风险要防        |

### 1.2 与「又一个聊天框」的本质区别

本产品的核心差异点是一条**用 Agent 教 Agent 的闭环**：

- **界面内**，四个各司其职的 AI Agent（讲解 / 点评 / 出题 / 答疑）驱动七步教学流程（讲解 → 示范 → 模仿 → 点评 → 可视化 → 练习 → 掌握判定），每一步都有对应的权限约束、评分维度与数据库落地；
- **界面外**，一个自动化学生 Agent 能代替人类学生**从第一讲学到最后一讲并毕业**——课程质量因此从主观判断变成了**可反复执行的命令**：12 讲全链路模拟（约 80 次真实模型调用）全部通过、解锁链零断裂，判分误判、掌握度断裂、材料缺口都是被这个学生 Agent 抓出来再修掉的。

这个闭环本身就是作品最大的创新点：**我们用被教的方法（Agent 编排）来保证教的内容（课程质量）**。

### 1.3 作品形态

纯 Web 应用（Next.js 16 App Router，React 19 + TypeScript），浏览器访问即用。后端仅承担 AI 能力接入（Agent 编排、模型调用、教学数据落库），没有任何「为后端而后端」的模块——27 个 API 端点每一个都能指到它服务的界面。

关键数字（2026-09-30 实测）：

| 项                  | 数值                                                        |
| ------------------- | ----------------------------------------------------------- |
| 课程                | 12 讲（2 讲语言速通 + 9 个 AI 工程模块 + 1 个复刻毕业课题） |
| 教学 Agent          | 4 个（讲解 / 点评 / 出题 / 答疑）× 7 个技能                 |
| 编排循环            | 4 个（教学 / 出题 / 点评 / 判分）                           |
| 可视化场景          | 9 个（每个 AI 工程模块一个，可交互播放）                    |
| API 端点            | 27 个（全部 Zod 契约校验）                                  |
| 数据表              | 18 张（含真实教学流量：375 条调用轨迹、130 条点评记录）     |
| 测试                | 36 组（33 纯函数/DB + 3 组真实模型回归），全绿              |
| 知识库              | `llm-wiki/` 66 个 Markdown 页面，唯一内容事实源             |

## 二、需求分析

### 2.1 目标用户与真实场景

目标用户是**零基础的 AI 协作学习者**：高职学生、刚入行的开发者、想把 AI 用进自己专业的人。他们的真实困境不是「没有教程」，而是三个具体的坎：

1. **学了概念不会用**——知道什么是 RAG，但不知道在自己遇到的问题里该怎么组装；
2. **AI 的输出没法判断对错**——模型说得头头是道，但不知道哪句是真会、哪句是在编；
3. **反馈缺失**——写完一段 Prompt、交完一份作业，没人告诉哪里好、哪里差、下一步练什么。

传统解法是「人教」：助教批改、老师答疑。这在规模上不可持续。本项目的解法是把「教、评、练、测」四个环节全部 Agent 化，且**每个环节的判断标准都写死在代码里**，不依赖模型措辞。

### 2.2 需求到功能的映射

| 真实需求                     | 对应功能                                                             | 服务的能力训练 |
| ---------------------------- | -------------------------------------------------------------------- | -------------- |
| 概念看不懂                   | 讲解 Agent 分步讲解 + 提问追问（流式输出，点开即有）                  | 意图表达       |
| 不知道正确做法长什么样       | 示范步：讲稿代码提取 + 分屏展示，确认后进入模仿                       | 上下文构建     |
| 想动手但怕写错               | 模仿步：任务卡明确「现在轮到你」，Monaco 编辑器内完成                  | 任务拆解       |
| 交了作业没反馈               | 点评 Agent 按维度打分 + 扣分问题清单 + 改进建议（真实落库）            | 结果校验       |
| 抽象概念看不见               | 9 个可视化场景：请求流、Agent 循环、检索管线、攻击-防护对比可交互播放 | 意图表达       |
| 练习不够、难度不匹配         | 出题 Agent 按掌握度定难度起点，变式练习 + 主/客观题判分                | 迭代修正       |
| 学了就忘、不知道下一步学什么 | 掌握度引擎 + 学习路径调整建议（基于下降、连续失败、错题积压）          | 任务拆解       |
| 作业截图不会描述             | 多模态点评：上传截图（≤3 张，自动压缩），视觉模型独立点评管线          | 结果校验       |

### 2.3 赛题约束的落实

赛题明确「以前端 Web 应用为主要呈现形态，后端服务仅作为 AI 能力的接入层」。本项目把它转化为一条可检验的架构自检标准：**没有为后端而存在的模块**。所有 API 端点都是某个界面的直接供给（数据获取、教学动作、流式回答），不存在报表后台、批处理任务这类「后端为其自身」的功能。模型调用、编排循环虽然运行在服务端，但它们是「AI 能力接入层」本身——前端应用的主要交互（七步教学、对话、可视化、报告）全部在浏览器完成。

### 2.4 与同类产品的对比

| 维度         | 通用 AI 聊天产品 | 视频课程平台 | 本项目                         |
| ------------ | ---------------- | ------------ | ------------------------------ |
| 教学判断     | 无               | 人工出题批改 | Agent 点评 + 代码写死的通过线  |
| 个性化       | 靠用户自己问     | 无           | 掌握度引擎驱动难度与路径       |
| 内容可信     | 无法保证         | 制作周期长   | 知识库是唯一事实源，可评审可 diff |
| 质量验证     | 无               | 无           | 学生 Agent 全链路模拟 12/12    |
| 反馈闭环     | 无               | 弱           | 错题本 + 提示词历史 + 学情报告 |
