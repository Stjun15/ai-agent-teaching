## 零、先定一件事：录本地，不录公网

**结论：录制用本地 `http://localhost:3000`（生产构建），公网地址只作为「在线演示」单独恢复，不进视频画面。**

2026-10-23 实测依据：

| 探测项                          | 结果                                                |
| ------------------------------- | --------------------------------------------------- |
| 公网 `8.149.130.30:80` TCP 连通 | **不通**（TCP 测试失败，首页与 /api/health 均超时） |
| 本地 `/api/health`              | `status=ok`，数据库 21 张表、Key 已配置、wiki 83 页 |
| 本地真实模型调用                | HTTP 200，首包 1.7 秒（DeepSeek V4 Flash）          |
| 本地登录 + 报告接口             | 200，eval 账号六项能力/成长曲线/错题数据齐全        |

三条不进视频的理由：

1. **公网当前不可用**。录到一半 502/超时，只能整镜重录；评审期间点开空白更致命。
2. **公网是明文 HTTP**。浏览器把 `http://<IP>` 视为**非安全上下文**：`crypto.randomUUID` 只能走降级逻辑、麦克风类接口不可用（录入入口已隐藏）；而 `http://localhost` 虽是明文却被当作安全上下文 —— 本地永远碰不到这条限制，也就验不出来。
3. **服务器是 1C1G**。SSE 流式与真实模型调用在本地是秒级，在小机上会明显卡顿，录出来「AI 很慢」是自伤。

**但要补一件事**：在线演示是**可选加分项**，要求「评审期间保持服务可用」。录完视频后应把公网恢复（`systemctl status ai-teaching` 先看服务是否在跑），并把地址与评审账号写进提交材料；**视频里不念公网地址**，避免画面与当时状态不一致。

> 若因故必须在队友电脑上录（本地不可行），完整替代方案与前置条件见 [一·附、备用分支：用公网录制](#一附备用分支用公网录制仅当本地录制不可行时启用)。

### 1. 启用前四条硬条件（全过才录，缺一条退回本地）

### 2. 本地没有、公网才有的四个坑

| 坑                         | 原因                     | 录制时怎么办                                                                                      |
| -------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------- |
| 流式输出一次性吐完         | nginx 反代没关 SSE 缓冲  | 开录前先跑一次追问确认是逐字出；不是就退回本地                                                    |

| 明文 HTTP 下安全上下文受限 | 浏览器规则，不是 bug     | 麦克风类入口已隐藏（也不能拍）；`crypto.randomUUID` 已由 `src/lib/uuid.ts` 降级兜住，不必手动处理 |

### 3. 必须改的四处

1. **第一节第 1 条**：不再 `pnpm build` / `pnpm start`，改为「确认公网可达 + 服务在跑」
   （`systemctl status ai-teaching` 由作者远程执行；**不要在 1C1G 上重新 build**，会打爆内存）。
2. **第一节第 2 条**：`eval` 账号必须存在于**服务器那份 `dev.db`**，且 8 讲掌握度齐全 —— 这一步只能在公网复验，不能假定。
3. **第一节第 3 条自检**：补上第 1 条的四项，再加一条「首屏 10 秒内出画面」。
4. **分镜 5 与分镜 8 的数字**：脚本里写死的「14 条错题」「4 条到期」「3 条路径调整」
   **一律换成公网页面上的实际值**再开口 —— 服务器库是另一份数据，不是本地这份。

### 4. 额外纪律

- **分镜 5 的订正会改服务器数据**：到期数会从 N 变成 N−1。复位要作者远程重跑
  `pnpm db:seed:auth`，队友做不到 —— 所以**先录分镜 8、再录分镜 5**，且录完立刻通知作者复位。
- **不要念公网地址，也不要说「已部署、随时可访问」**：与第五节第 2、5 条同一口径。
- 万一现场出现白屏、502、模型欠费 403：**当天不要硬录**，改用本地素材。
  异地无人值守时，一次卡顿就要重录一整镜。

### 分镜 3（2:00–3:05 · 概念讲解页停留 65 秒）核心功能①：讲解 Agent

**画面时间轴**：

| 秒    | 画面                                                                |
| ----- | ------------------------------------------------------------------- |
| 0–5   | 进入讲解页，**讲稿直接出现**（不点任何按钮），光标不输入            |
| 5–15  | 在输入框提问，例如「为什么一定要把 assistant 的消息传回去？」并发送 |
| 15–40 | 让流式输出自然打完（不要加速），中途不要切页                        |
| 40–55 | 光标指向答案上方的「本节参考了知识库哪几页」引用条目                |
| 55–65 | 点开思考过程折叠面板，给 5 秒特写后收                               |

**口播**：

> 先看概念讲解。讲稿是提前生成、直接写进缓存的，点开就在，不用等模型。
> 学生随时可以追问，回答逐字流式输出；在第一个字出现之前，先能看到模型的思考过程。
> 答案上方会标出这一节参考了知识库的哪几页——检索是关键词加向量的双路召回，再用 RRF 融合。
> 我们拿 22 道评测题做过三路对比：纯向量路 recall@3 是 95.5%，关键词路 72.7%，
> 混合反而只有 90.9%——融合稀释了向量的命中。这个倒挂我们没有藏，原样写进了技术文档，
> 也列在优化清单里。

**实拍口径**：讲稿秒出；问答流式打字机；引用条目（来源页名）；思维链面板。
