# AI 技术方案

> 一句话：不是「接一个模型做问答」，而是把九个 AI 工程模块（API → 提示词 →
> Agent Loop → 工具 → RAG → Wiki → 多 Agent → MCP → 安全）做成可上手的
> 教学流程，每一步都有对应的运行代码与可视化场景。

## 一、能力地图

教学链条是**概念 → 场景 → 项目**三层落地：每个模块都有概念页、一个可播放的
可视化场景、以及一个可动手改的项目模板。

| 模块（概念页）  | 可视化场景          | 项目             |
| --------------- | ------------------- | ---------------- |
| `llm-api`       | 请求-响应流程       | 01 聊天机器人    |
| `system-prompt` | 角色滤镜对比        | 02 人格机器人    |
| `agent-loop`    | Agent Loop 天气查询 | 03 天气 Agent    |
| `tool-calling`  | 工具调用链          | 04 多工具 Agent  |
| `rag`           | 检索-生成流程       | 05 RAG Agent     |
| `llm-wiki`      | RAG vs Wiki 对比    | 06 Wiki Agent    |
| `multi-agent`   | 多 Agent 通信       | 07 多 Agent 系统 |
| `mcp`           | MCP 调用流程        | 08 MCP Agent     |
| `ai-safety`     | 攻击-防护对比       | 09 安全 Agent    |

支撑这条链条的运行时由 **4 个 Agent × 7 个 Skill** 组成，权限写死在代码里：

| Agent      | 默认 Skill          | 允许使用的 Skill                                                             |
| ---------- | ------------------- | ---------------------------------------------------------------------------- |
| 讲解 Agent | `explain-concept`   | `explain-concept`、`trigger-visualization`、`answer-question`                |
| 点评 Agent | `validate-prompt`   | `validate-prompt`、`validate-tool`、`validate-code`、`trigger-visualization` |
| 出题 Agent | `generate-question` | `generate-question`                                                          |
| 答疑 Agent | `answer-question`   | `answer-question`、`explain-concept`                                         |

## 二、四层执行架构

| 层       | 载体          | 内容                                       |
| -------- | ------------- | ------------------------------------------ |
| 1 身份层 | System Prompt | Agent 是谁、职责、行为准则                 |
| 2 技能层 | Skill 文件    | 具体任务怎么做（步骤、评分维度、通过条件） |
| 3 知识层 | LLM Wiki      | 概念、反模式、评分标准、学生画像           |
| 4 编排层 | 工作流代码    | 什么时候调用谁、读哪些页面、失败怎么办     |

组装发生在 `runtime.ts` 的 `composeAgentPrompt`：身份层与技能层拼成一个
system prompt（`systemPrompt + "\n\n---\n\n" + skillContent`），
情境数据单独走用户消息 —— 技能进 system prompt 而不是用户消息，
是为了让「怎么做」不随每一轮输入漂移。

## 三、权限由代码控制，不靠模型自觉

两条同构的约束：

- **Skill 白名单**：`allowedSkills` 里没有的 Skill，在 `runAgent` 入口
  **直接抛错、不发给模型**。出题 Agent 拿不到 `validate-code`，讲解 Agent
  触发不了 `validate-prompt`。
- **工具白名单**：SDK 的 `tools` 字段是总白名单，同时作用于内置工具与自定义工具。
  踩过的坑是自定义工具注册之后仍会被它统一过滤 —— 自定义工具必须按名字列进 `tools`。

再加一条结构约束：真正干活的 `executeAgent` **不导出**。绕过它就跳过了权限检查
与 Zod 校验，所以它只允许被 `runAgent` 调用。

## 四、结构化输出、重试与兜底

模型输出全部要求 JSON，并**逐次尝试跑 Zod 校验**：

| 环节 | 做法                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------- |
| 校验 | 每次尝试都解析 JSON 并对该 Agent 的 schema 校验                                                |
| 重试 | 失败时把 `previousError`（Zod 报错）与 `previousRawText`（模型原话）回填给模型，让它知道错在哪 |
| 上限 | `DEFAULT_MAX_RETRIES = 2`，即最多 3 次尝试                                                     |
| 成本 | token 按尝试**累加**：重试是真实成本，trace 里能看到「这次花了三次才过」                       |
| 兜底 | 三次都不合法则用 `fallback()`，并打上 `usedFallback` 标记                                      |

兜底有两条硬原则：**诚实**（必须能被识别出来，文案里写明「本次自动评分未生效」）
与**不阻断**（给学生继续走的方向）。评分兜底刻意给「未评分」而不是假分数 ——
给一个看起来像正常评分的假分数，是最坏的一种兜底。

## 五、编排层：四个循环

| 循环              | 输入 → 输出                   | 特点                                                        |
| ----------------- | ----------------------------- | ----------------------------------------------------------- |
| `teaching-loop`   | 教学状态 → 讲解/练习/校验步骤 | 按 phase 分派，贯穿讲解 Agent 与点评 Agent                  |
| `question-loop`   | 模块 + 数量 + 掌握度 → 题目   | 模块级调用，**不隶属会话**（trace 里 `session_id` 为 NULL） |
| `validation-loop` | 学生作业 → 点评 + 是否通过    | 通过线是代码写死的三条硬条件，不依赖模型措辞                |
| `assess-loop`     | 题目 + 学生答案 → 评分        | 客观题走规则判分、不调模型；主观题复用点评 Agent            |

「通过线不依赖模型措辞」是关键设计：模型说「很好、很棒」不构成通过，
避免「其实没过却被判过」。判定逻辑在代码里，模型只提供维度分与问题清单。

## 六、检索与引用（说清楚它不是向量检索）

知识层的检索是**本地加权关键词检索**（`src/wiki/query.ts`），不是 embedding 检索：

- 打分 = 字段权重 × 命中次数 + 短语奖励，累加和**没有上界**；
- 因此不能直接当 0~1 的相关度用：除以参考分 `REFERENCE_SCORE = 40` 再截断到 1；
- 低于 `MIN_RELEVANCE = 0.15` 的命中直接丢弃 —— `query` 的门槛只是 `score > 0`，
  一个常用词就能让几十页过线，全发给学生是噪音。

这套数字来自对权重公式的推算，**没有用真实语料标定过**。若发现引用经常不相关，
应先调这两个常量，而不是怀疑检索坏了。

引用在模型回答**之前**以 SSE 事件发给前端：检索是毫秒级的，学生先看到「本节参考了
哪几页」，再看到逐字生成的答案，等第一个 token 的空档不被浪费。

规格文档里的 `knowledge_embeddings` 表**没有建** —— 检索不走向量，不需要它。

## 七、上下文预算

多轮对话的历史是全文进 prompt 的，长会话会线性吃 token。当前有两道限制：

- 条数：只取最近 20 条进 prompt（`HISTORY_LIMIT`）；
- 字符：`HISTORY_CHAR_BUDGET = 4000`，超出时**从最旧整条丢弃**，
  最新一轮无条件保留（截半条历史会让模型读到断句，比丢掉更糟）。

角色归并：库里六种 role（student/teacher/reviewer/examiner/assistant/system）
到模型眼里只有「学生」与「助手」两种，system 消息不进历史 —— 区分六个说话人
只会让模型以为房间里站着一堆人。

长会话的正解是摘要压缩，那是另一个量级的工作，当前明说没做。

## 八、安全防护：四道门

| 门       | 位置                                               | 拦什么                                                                                       |
| -------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 输入过滤 | 对话路径（`session/[id]/message`、`agent/answer`） | 提示注入：模块 9 的三条危险词 + 结构性注入模式（英文忽略指令、越权角色扮演、套取系统提示词） |
| 输出打码 | `runAgent` 出口，递归遍历整个输出对象              | 凭据（`sk-` 密钥、Bearer 令牌），按结构性模式认，不读环境变量                                |
| 限流     | 每个受限端点第一行                                 | 误刷与脚本循环；进程内固定窗口，边界已在代码中声明                                           |
| 权限     | `runAgent` 入口                                    | Skill 与工具的越权调用                                                                       |

两处刻意的**不拦**，同样是设计而不是遗漏：

- **提交作业路径不过滤**（`validate`、`answer-grade`）：模块 9 的作业本身就是
  写攻击样例与防护方案，拦了学生没法交作业；
- **演示场景不自己抄一份规则**：场景的过滤规则从 `lib/security` **转出**同一份
  引用（有测试用引用相等钉住），否则会演成「在演安全，而不是讲安全」。

拦下的输入**不落库**：否则它会进入历史，之后每一轮都被重新喂给模型。

## 九、可观测与评测

`agent_traces` 记录每次 Agent 调用的 `agent` / `skill` / `input` / `output` /
`durationMs` / `tokens` / `retries` / `success`。其中 `retries` 是最有信息量的字段：
它把「一次回答背后试了几次」暴露出来，而这在界面上是看不见的。
真实流量已经产生记录（`session_id` 是真实 UUID，其中一条 `retries = 2`）。

测试分两档，由 `scripts/run-tests.mjs` 逐组汇总（一组失败不影响其它组继续跑）：

- **纯函数与 DB 集成**（14 组）：Markdown 解析、客户端身份、分数量纲、主题偏好、
  沙箱清单、可视化场景、项目模板、教学循环 / 结果表 / 闭环、Trace 接线、
  提示词预算、安全过滤、限流。
- **真模型回归**（2 组）：点评 Agent 与讲解 Agent 各一组，慢、花钱、
  且有固有的间歇失败 —— 因此**不串联执行**，否则前一组红了后一组根本不会跑。

代码门禁是 `npm run check`（ESLint + Prettier + `tsc --noEmit`）。
类型层面还有一组「活断言」：故意删掉 `AGENT_IDS` 里的一个值，`tsc` 会报错，
而不是静默通过。

## 十、已知边界（诚实清单）

- **没有向量检索**，也没有 embedding 表；检索质量靠关键词权重调参。
- **工具面很窄**：目前只有 1 个自定义工具（计算器），工具调用模块的教学价值
  主要靠场景与项目模板承载。
- **`api-auth.ts` 不是真鉴权**：它只解析「你是哪个学生」并确认存在，
  挡不住假冒。真正的登录体系尚未实现。
- **限流是进程内实现**：多实例部署各自计数、重启清零，不构成分布式防护。
- **`errors` 与 `prompt_history` 没有写入路径**：有查询端点、有仓库层，
  但没有任何代码往里写 —— 报告页的错题本与提示词历史因此恒为空。
- **`fallback` 的识别靠调用方自觉**：编排层看到 `usedFallback` 时不应据此更新
  掌握度，这是约定而不是类型约束。
