## 1. prompt-rubric.md

```markdown

type: rubric

name: Prompt 评分标准
related_concepts: [system-prompt]
---
# Prompt 评分标准
## 维度与权重
| 维度 | 权重 | 评分要点 |
|---|---|---|
| 角色定义 | 25% | 身份清晰、职责明确、能力边界清楚 |
| 工具描述 | 25% | 工具名、参数、用途、返回值准确 |
| 输出格式 | 20% | 结构化、字段明确、示例清晰 |
| 边界条件 | 15% | 异常、空输入、多轮对话、兜底 |
| 简洁性 | 15% | 无冗余、无矛盾、无模糊 |
## 各维度评分细则
### 角色定义（25 分）
- 身份清晰（10 分）：明确说明 Agent 是谁
- 职责明确（10 分）：说明能做什么、不能做什么
- 能力边界（5 分）：说明不确定时怎么办
### 工具描述（25 分）
- 工具名称（5 分）：动词+名词
- 工具用途（10 分）：说明什么时候用
- 参数说明（5 分）：类型、必填
- 返回值（5 分）：说明返回什么
### 输出格式（20 分）
- 结构化（10 分）：JSON / Markdown / 表格
- 字段明确（5 分）：字段名和类型
- 示例（5 分）：给出输出示例
### 边界条件（15 分）
- 异常处理（5 分）：出错时怎么办
- 空输入（5 分）：输入为空时怎么办
- 多轮对话（5 分）：上下文怎么处理
### 简洁性（15 分）
- 无冗余（5 分）：不重复
- 无矛盾（5 分）：不自相矛盾
- 无模糊（5 分）：不用"尽量""可能"
## 扣分规则
| 问题 | 扣分 |
|---|---|
| 缺少角色定义 | -20 |
| 工具描述缺少参数类型 | -10 |
| 未定义输出格式 | -15 |
| 未考虑异常 | -10 |
| 出现矛盾指令 | -15 |
| 模糊词汇 | -5/处 |
| 角色定义少于 10 字 | -10 |
## 评分等级
| 分数 | 等级 | 说明 |
|---|---|---|
| 90-100 | 优秀 | 可直接使用 |
| 75-89 | 良好 | 少量改进 |
| 60-74 | 及格 | 需修改 |
| <60 | 不及格 | 重写 |
## 通过条件
- total_score >= 75
- 角色定义 >= 60% 权重分
- 无严重错误
```

```markdown
type: rubric

---
# 工具定义评分标准
## 维度与权重
| 维度 | 权重 | 评分要点 |
|---|---|---|
| 名称 | 20% | 动词+名词，语义清晰 |
| 描述 | 30% | 用途、适用场景、返回内容 |
| 参数 | 30% | 类型、必填、描述、默认值 |
| 错误处理 | 20% | 异常返回、参数校验 |
## 各维度评分细则
### 名称（20 分）
- 动词+名词（10 分）：如 getWeather
- 语义清晰（10 分）：一看就知道做什么
### 描述（30 分）
- 用途（10 分）：说明做什么
- 适用场景（10 分）：说明什么时候用
- 返回内容（10 分）：说明返回什么
### 参数（30 分）
- 类型（10 分）：每个参数有 type
- 必填（10 分）：有 required 字段
- 描述（10 分）：每个参数有 description
### 错误处理（20 分）
- 异常返回（10 分）：出错时返回 error
- 参数校验（10 分）：空值、类型错误处理
## 扣分规则
| 问题 | 扣分 |
|---|---|
| 名称用名词 | -10 |
| 描述只说"查天气" | -10 |
| 参数缺少 required | -10 |
| 参数缺少 description | -5/个 |
| 未考虑查不到 | -10 |
## 通过条件
- total_score >= 75
- 参数 >= 70% 权重分
- 无严重错误
```
